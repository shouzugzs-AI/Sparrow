## 1. P0-2：`重复` 的循环化

### 1.1 怎么用

```powershell
# 默认仍是展开（V0.1.1 行为，字节不变）
sparrow m.sparrow --asm vmlm-asm.exe --consts-dir W -o m.vmb
# 打开循环化：N 层 → 1 份模板 + LOOP_CNT + LAYERB
sparrow m.sparrow --asm vmlm-asm.exe --consts-dir W --loop-repeat -o m.vmb
```

发射形状（`t = 稀疏 维度=4 连接=2 重复24次` 的 `t` 组）：

```
    SHAPE   t__24__in, 1, 4          ; 进位槽（循环体的进与出都走它）
    COPY    t__24__in, EMBED_out
    SHAPE   t__24__ctr, 1, 1         ; 计数器/步长槽必须是**激活槽**
    COPY    t__24__ctr, t__1_iters
    SHAPE   t__24__ls, 1, 1
    COPY    t__24__ls, t__1_lstride
    SHAPE   t__24__ns, 1, 1
    COPY    t__24__ns, t__1_nstride  ; = -24×192
t__24__l1:
    SHAPE   t__24_col, 4, 1          ; ← 模板：槽位用第 24 份，常量引用第 1 份
    SPARSE_MATVEC t__24_col, t__1_off, t__1_src, t__1_W, t__24__in
    TRANSPOSE t__24_out, t__24_col
    COPY    t__24__in, t__24_out
    LAYERB  t__24__ls                ; base += 192
    LOOP_CNT t__24__ctr, @t__24__l1  ; 减完再判
    LAYERB  t__24__ns                ; base 还原
```

设计与取舍（每条理由都在代码注释里）：

| 决定 | 为什么 |
|---|---|
| 输出槽沿用**最后一份**的名字（`t__24_out`） | 下游 `连接`/`前向` 的接线与展开版**一字不改** |
| 循环输入先 `COPY` 进**进位激活槽** | 常量槽会被 `layer_base` 平移，共享常量（词元 id）被平移就错（E3） |
| 计数器/步长用**激活槽** | `LAYERB`/`LOOP_CNT` 读值走 `const_ptr`，常量槽同样会被平移（E2） |
| 收尾 `LAYERB -N×步长` | N 圈各推进一次，结束时 base = N×stride（E4） |
| 循环控制常量放**池尾** | 池里"第 r 份 → 第 r+1 份"的偏移差必须恒等于步长，中间插常量就破坏它 |
| `.args` 仍列全 N 份 | 池必须连续，`LAYERB` 靠它走路；也正是"与展开版同一批权重"的前提 |
| 默认**不开**循环化 | 不动 V0.1.1 的既有产物（49 项旧测试与 e2e 三方对照全绿） |

### 1.2 三项验收判据

| 判据 | 结果 | 证据 |
|---|---|---|
| **24 层指令数 == 1 层（O(1)）** | ✅ | 24 层 **21 条** == 6 层 **21 条**；展开 6 层 24 条（每层 3 条）。`tools/loop_ab.ps1` §1 |
| **引擎输出与展开版逐字节相同** | ✅ | N=6：循环版 `0.274968 0.606448 0.351826 0.290492` ≡ 展开版，**差异字节 0** |
| `loss_hash` 一致 | ⛔ | 见 §2.6（前端范围内不可测） |

**为什么 A/B 只能用 N=6 而不是 N=24**：24 层的**展开**版汇编不出来 ——
`SPARSE_MATVEC` 把权重槽压进 `fl` 低 6 位，槽号必须 ≤ 63，展开版每层 3 个常量槽，
第 21 层的权重槽号就是 66，汇编器硬报错（陷阱 B9）。这反过来是 P0-2 价值的最强论据：

> 对 ≥21 层的稀疏模型，循环化不是优化，而是**唯一可行的编译路径**。

### 1.3 判据不是恒真的（can-fail）

| can-fail | 结果 |
|---|---|
| 步长 +64 B（192→256） | ✅ 输出/退出码变化：引擎 `exit=9 SPARSE_MATVEC: offsets out of range` |
| 步长 +192 B（跳一层） | ✅ 变化（`exit=9`，`j=2 o0=1 o1=0`） |
| 步长 −64 B | ✅ 变化（`exit=9`） |
| 恢复 192 B | ✅ 输出回到原值（证明前三条不是噪声） |
| **每层权重必须不同** | ✅ 生成器用 24 个不同 seed，断言两两逐元素最小差 `0.987` |

> 若 24 层用同一套权重，步长错一位也"逐字节相同"—— 判据恒真。这是本轮最容易被偷懒绕过的地方。

### 1.4 步长是**实测**的，不是前端猜的（`E210`）

前端仍会算一份**预测**步长（`--backend vml` 模式下没有汇编器可读：`Σ 补齐(每块字节, 64)`），
但 `--asm` 一旦产出 `.vmb`，就**必须**拿 META 常量表对账（`src/vmbmeta.rs` + `verify_loop_groups`）：

1. **池序 = 清单序**：逐条比 `rows/cols/len`；
2. **步长恒定**：每份每位置的相邻偏移差必须相等；
3. **实测步长 == 预测步长**。

任何一条不满足 → `E210` + **删掉产出的 `.vmb`** + 退出码 1。
对账逻辑的 can-fail 用**故障注入假汇编器**（`examples/asm_fault_inject.rs`，
以真 `.vmb` 为底篡改 META，假装成功退出 0）端到端验证：

```
5 E210 步长不恒定   : PASS  ...第 1→2 份第 0 个常量（0 起）差 192 B... 单一增量假设被打破
5b 不留下不可信产物 : PASS  对账失败后 .vmb 已删除
5c E210 条数不符    : PASS  ...清单 25 条，.vmb 里 24 条
```

另外还有 4 条库级 can-fail（偏移扰动 / 条数谎报 / 长度谎报 / magic 破坏），
在 `tests/loop_repeat.rs::verify_accepts_consistent_pool_and_rejects_perturbations`。

### 1.5 新增的硬校验

| 码 | 触发 |
|---|---|
| `E210` | 循环步长对账失败（池序/恒定/与预测不符） |
| `E212` | 步长或 N×步长不能被 **f32 精确表示**（`LAYERB` 的增量是 f32，会被 `as usize` 静默截断） |
| `E106` | `重复` 组的模板自己有汇入 + 开了 `--loop-repeat`（明确拒绝，不悄悄退回展开） |

### 1.6 遗留（不假装做完）

- **`loss_hash` 未接**：需要 vmlm 侧的 24 层训练链（数据 + 训练器），前端拿不到。
  前端范围内能测的就是"输出逐字节相同"，已测。
- 循环化的槽位仍是**朴素分配**（不省激活槽）—— 那是 V0.1.3 的"槽位复用"。
- 汇入 + 循环化的组合不支持（`E106`）：循环体每圈都要重新汇入（进位槽不止一个）。
- **非最后位置**的循环组 + 后续常量：已由 `-N×stride` 还原覆盖，且有 A/B 与 can-fail；
  但"多个循环组串联"只有单组实测（`tests/loop_repeat.rs` 有 1 组的断言，未覆盖 2 组叠加）。

## 2. V0.1.3：汇入（多前驱合流）

### 2.1 语法（**不新增关键字**，复用既有 `连接`）

```
模型 resadd:
  嵌入 词表=8 维度=4
  t = 稀疏 维度=4 连接=2
  mg = 线性 输出=4            # 合并方式省略 ⇒ 等宽自动选"相加"
  连接 嵌入 t
  连接 t mg                   # mg 的前驱 = t
  连接 嵌入 mg                # mg 的前驱 = {t, 嵌入} ⇒ 汇入
  前向 嵌入 mg
```

- **一条 `连接` 指向同一层 = 一个前驱**；一个层有两个及以上前驱 = 汇入。
- 合流方式：**等宽 → 相加（`EWADD`）**，**不等宽 → 拼接（`CONCAT`）**；
  也可显式写 `合并=相加|拼接`（别名：`汇入`/`合流`/`残差`/`融合`/`merge`/`residual`/`concat`…）。
- 为什么按宽度自动定而不是"猜残差"：宽度相等是**可判定**的事实；
  猜测错就是静默算错，而 `EWADD` 在不等宽下根本没有定义。
- 3 个以上前驱**左折叠**：相加可以就地折叠（引擎 `EWADD` 是"先读两个、再写同下标"，
  `dst == a` 安全）；拼接不行（宽度在长大），每次折叠用临时槽 + `COPY` 搬回。
- 前驱顺序 = `连接` 语句出现顺序：相加可交换所以无感；**拼接不可交换所以是语义**。

### 2.2 图与维度的改动

从"单链"升级为"单入口 DAG"：

| 项 | 之前 | 现在 |
|---|---|---|
| 前驱 | `pred: Option<usize>` | `preds: Vec<usize>`（空 = 链首，≥2 = 汇入） |
| 定序 | 顺着 `pred` 单向走 | **Kahn 拓扑序**（每步取下标最小的就绪节点 ⇒ 确定性） |
| 链首 | 必须恰好 1 个 | 仍然必须恰好 1 个（只支持一个数据入口），0 个 = 环 |
| 合流 | `E100`（不支持） | 自动/显式选 `EWADD`/`CONCAT`，宽度矛盾才报 `E100` |

### 2.3 验收：与**独立 numpy 参考逐字符相同**

三个形状 + 两个顺序对照模型，全部与 numpy 独立算出的参考**逐字符相同**：

| 模型 | 合流 | 引擎输出 == 参考 |
|---|---|---|
| `residual_add` | 相加（等宽 4），`y=(e+s)·W^T+b` | ✅ `0.143211 1.263532 -1.372653 -0.160191` |
| `residual_concat` | 拼接（4+4=8），`y=[s;e]·W^T+b` | ✅ `-0.773504 0.854695 2.113780 -0.958526` |
| `residual_three` | 3 前驱相加，左折叠两次 | ✅ `4.502551 1.331908 0.514215 0.972272` |
| `residual_dup` | 两个**逐位相同**的前驱相加 | ✅ `1.360756 0.000000 0.000000 0.926220` |
| `residual_add_swapped` | 相加，`连接` 顺序颠倒 | ✅ 与 `residual_add` **逐字符相同**（可交换） |
| `residual_concat_swapped` | 拼接，`连接` 顺序颠倒 | ✅ **必须不同** → 实测 `-0.357654 … ≠ -0.773504 …` |

> **本轮最有价值的工具发现**：引擎的 `print_f32`（`interp.rs:2459`）是**截断**，不是四舍五入。
> 一开始我用 numpy 的 `%.6f`（四舍五入）做参考，于是**每个数都差 1 个末位**、
> 且方向一致 —— 这正是 V0.1.1 报告里"numpy 0.975112 / 引擎 0.975111"
> 那个一直没解释的差异。把参考格式改成**复刻引擎的截断**后，比较升级为
> **逐字符**，容差被彻底取消（容差比较会放过真实的算子错误）。

can-fail（判别性）：故意写错的合流（相加写成相减 / 拼接顺序反了 / 相乘）
与正确参考的最大差分别是 `0.676` / `2.357` / `6.222`，比打印精度高 6 个数量级。

### 2.4 语义边界（都有名字）

| 码 | 场景 | 实测 |
|---|---|---|
| `E100` | 不等宽还要相加（4 / 8） | `层 mg 要相加，但前驱宽度不等（4 / 8）—— 相加没有定义` |
| `E100` | 该层自己写的 `输入=` 与汇入宽度冲突 | `声明输入宽度 4，但它的 2 个前驱汇入后是 8（拼接(CONCAT)）` |
| `E100` | `合并=` 的值不认识 | 给候选：`相加 (add/residual)` / `拼接 (concat)` |
| `E102` | 成环（0 个链首） | `图里有环（没有任何链首）` |
| `E106` | 汇入 + 循环化 | `重复组 t 的模板有 2 个前驱（汇入），循环化暂不支持这个组合` |

### 2.5 汇入的数值验证为什么可信

1. **独立参考**：numpy 自己算（不读 `.vml`、不调引擎），且**逐字符**比对；
2. **形状覆盖**：相加 / 拼接 / 3 前驱 / 逐元素尾巴（不经过 GEMM 舍入）；
3. **顺序覆盖**：相加可交换（逐字符相同）与拼接不可交换（必须不同）各一条；
4. **can-fail**：故意写错的参考值差异 ≥0.676（判据不恒真）；
5. 四个语义边界都由**具名错误**拒绝，而不是静默产生一个错模型。

### 2.6 `loss_hash`

任务书里 P0-2 的第三条判据是"`loss_hash` 一致**如果可测**"。
不可测：`loss_hash` 来自 vmlm 侧的训练/前向链（`vmlm-b1-full` + 数据），
Sparrow 前端只产出 `.vmb`，没有训练环。前端范围内可测的等价物是
"同一批权重、同一输入 → 输出逐字符相同"，已测（§1.2、§2.3）。
建议在 V0.1.4 单列一条"前端产物接 vmlm 训练链"的任务，而不是在前端假装测过。

## 3. 不可测/边界判断（明确写出来）

1. **P0-2 的 A/B 只能到 N=6**：N=24 的展开版被汇编器的 6 位权重槽字段挡住（B9）。
   我用 N=6 做逐字节 A/B，用 N=24 做"指令数与 N 无关"（21 == 21）。
   这两条加起来覆盖了 P0-2 要表达的全部性质，但**"24 层循环版 vs 24 层展开版"这个更直观的对照不存在**——
   不是没做，是那条路装不出来。
2. **`.args` 前缀相同（而非逐字节相同）**：循环版比展开版多 3 条循环控制常量，落在池尾。
   等价的说法是"常量池的既有部分一字不动"。
3. **汇入 + 重复组内部**（既重复又有多个前驱）不支持：`E106` 明确拒绝。
4. **多循环组叠加**：只实测 1 个循环组（含"循环后有常量访问"的情形）；2 组同时存在有代码支持但没有端到端实测。
5. **注意力块未做**：见 §5，情报已收敛成可直接开工的契约表。

## 5. 下一步开工清单（按依赖排序，情报已就绪）

1. **注意力块展开**（当前 `E104`）。汇编器里**没有** `ATTEN`/`HEAD` 这类助记符，
   必须自己组合：`GEMM`(QKV) → `SLICE`(拆头，注意第 4 个操作数是**汇编期专用**的宽度)
   → `SCALE`(1/√d) → `GEMM`(QK^T，`nn`) → `SOFTMAX sc, sc, causal`（causal 是裸 flag）
   → `GEMM`(·V，`nn`) → `CONCAT`(并头) → `GEMM`(输出投影)。
   已知雷：`BMM` 在 `k==0` 时**整除零 panic**（不是 exit(9)）；`SLICE`/`CONCAT` 无守卫；
   拆头期间"行 = 头、列 = 头内维度"的布局必须自己拿 `.vml` 显式 `SHAPE` 钉死。
2. **汇入 + 重复组内部**：把进位槽从 1 个扩成"每前驱一个"，让残差块可以循环化。
3. **槽位复用**：按生命周期回收（链式结构里只有被分叉读到的槽需要留）。
   判据仍是"与不复用版逐字节相同"，且要加 can-fail（复用错位会让**相邻槽**被覆盖）。
4. **路径 2 后端（Rust 拼装库）**：`.spar → Rust 源码`（`struct`+`impl`、`include_bytes!`、
   `fn forward()`/`fn backward()`），CLI 已占位 `--backend lib --lang rust`；
   判据：同 seed 同输入 → 两个后端输出逐字符相同。
5. **序列长度进架构 IR**：现在模型输入固定 `T=1`；`heads`/`seq` 属性已在 `ATTRS` 里。
6. **稀疏拓扑接 `conn_sparse`**：现在是固定规则 `(j*k0+t) mod dim`；
   接训练侧的窗口拓扑 + top-k（`TOPK_BY_STRENGTH` + `selgate`）。
7. **多个循环组叠加**的端到端实测（现在只有 1 组）。
