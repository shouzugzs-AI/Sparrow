# 更新日志

本文件记录**已验收**的版本。写法约定：每个版本给出「做了什么 → 关键判据（可假）→ 复现命令」，
数字都是实测值；不确定的事写"没做/没验"，不写"应该没问题"。
逐项的完整证据在对应的 `REPORT*.md` 里。

小节归档，不再逐一改动旧报告）。

**发布前加固**
* **行尾归一化**：6 个文件（`src/main.rs`、`src/vmlgen.rs`、4 个 `examples/attn_*.sparrow`）
  在 index 里仍是 CRLF/混合，编辑一次就会变成整文件假 diff（实测 1,318 / 3,922 行）。
  判据：去掉 CR 后的 SHA-256 不变（6/6）、`git diff --ignore-cr-at-eol` 为空、
  `git ls-files --eol` 里 `crlf/mixed` 6 条 → 0 条。提交 `d752b9a`。
* **`tools/*.ps1` 去机器相关硬编码**：`$root` 改从 `$PSScriptRoot` 推导，`$vmlm` 走
  `$env:SPARROW_VMLM_ROOT` 或同级目录推导（找不到就硬失败），`$git` 从 PATH 取。
  判据：13 个脚本精确替换且 BOM/行尾保留；从 `C:\` 作为 CWD 也能跑通；can-fail 指向不存在的
  vmlm 目录时 `exit=1`。提交 `71055fb`。
* **文档同步**：`docs/REPO.md` 的文件数/测试数/CAA 说明、`tools/*.ps1` 注释里写死的驱动数与测试数、
  `REPORT_V015.md` 里"产物不依赖引擎"的措辞（准确说法：不依赖**引擎二进制/VM**，但**静态链接
  引擎的源码 crate** `vmlm-ops`）全部改准。

**新功能（都带 can-fail 判据）**
* **注意力每头暂存槽接入复用**：`q/k/kt/v/s` 五个角色槽 H 头轮流借，`c`（每头输出）仍按头分开，
  拼头目标借 `_q`。实测（头=2、T=4）：槽位 30 → 24，**激活区 1152 B → 768 B（−33.3%）**，
  注意力块目的槽名 17 → 11（差额 == `5×(H−1)+1`）；输出**逐字符不变**。
  can-fail：把 `c` 也共用（一行改动）⇒ 四个注意力模型的输出**全部变**。提交 `9e968b0`。
* **训练路径**：语言新增 `损失 均方` 与 `反向`（`Stmt::Loss` / `Stmt::Backward`、`.spar` 里
  `LOSS mse` / `BACKWARD`）；前端按拓扑反序发射 `MSE_BWD` / `GEMM_BWD_W` / `GEMM_BWD_X` /
  `BIAS_BWD` / `ACT_BWD`，并 `PRINT` 每个参数的梯度。
  判据：引擎解析梯度 vs **numpy 中心差分**，最大相对误差 **9.8e-06**；
  numpy 解析 vs 中心差分 3.0e-07；扰动权重 ⇒ 梯度必变；官方运行时 SHA256 前后一致。
  边界：只接 `线性` + `激活`；与 `--slot-reuse`/`--loop-repeat` 互斥（`E114`）；
  AOT 不支持（`E115`）；**没有参数更新**（训练循环仍是 `E111` 边界）。提交 `bb9124f`。
* **int8 铺到注意力投影**：`Wq/Wk/Wv/Wo` 四组 `gemm_nt` 改用 `gemm_nt_int8`（反量化在核内）。
  判据：精确可表示（`w=q/64`）时 f32 与 int8 输出**逐字符相同**；动一行投影 scale ⇒ 最大差
  0.006678；体积比 == 公式 `4/(1+4/K)` = 2.000。提交 `a580919`。

**测试与陷阱库**
* `cargo test` 85 → **89 passed / 0 failed**；验收驱动 10 → **11 个**（新增 `tools/train_ab.ps1`）；

* `docs/TRAPS.md` 67 → **73 条**，新增：**C8**（`x`/`lin` 这类关键字别名当实例名会把报错指向下一行）、

## [0.1.5]

* 描述语言**纳入 git**（基线提交 `34e6904`），`.gitattributes` 对齐上游行尾策略；
  `examples/` 下的生成物**入库当指纹**，换来一条强不变量：跑完全部驱动 `git status` 必须为空。
* `tools/verify_all.ps1`（一条命令 = `cargo test` + 全部驱动 + 干净不变量）；
  `tools/repo_boundary_probe.ps1` + `docs/REPO.md`（独立仓库 vs 并入引擎目录，含 can-fail 判据：
  删掉嵌套 `[workspace]` 行必须失败）。
* **AOT vs 解释器**进程内同口径基准（`--bench-iters`）：AOT 每层快 3.3%~7.6%；
  诚实结论——两条路共用同一套 AVX2 内核、负载是内存带宽受限，"比解释器快"最多说到 ~5%。
  过程中发现一个**恒真基准**（NaN 被截断式打印洗成 `0.000000`，导致"逐字符相同"假通过），
  靠 can-fail 判据抓到。
* `--backend lib` 支持**循环化的 `重复` 组**（源码长度 O(1)：一份代码 + N 份常量），
  并与 `.vmb` 逐字符一致；顺带把源层 `重复` 的 panic 改成命名诊断 `E110`。
* **槽位复用扩展到暂存槽**：汇入中间槽、循环进位槽/汇入槽/计数器/步长槽也回收，
  12 层残差激活区 1664 B → **256 B**；结构判据直接数槽名（12 → 1）。
* **序列 `T>1` 的嵌入链首**（逐行查表 + 拼行）；**顺带修掉一个静默错答案**
  （T>1 + 循环时进位槽行数写死成 1，静默只算第一行、退出码 0）。
* **int8 线性层权重**（per-输出行 scale）：k=1 与 f32 逐字符相同、k>1 差值有界、
  动一行 scale ⇒ 差值远超界、体积比按公式核对；`.vmb` 路径硬拒绝（`E109`）。
* **`backward()` / 训练路径**：当时判定"不落地"，给出**可判定边界** `E111`
  （把"语言没这个功能"和"你打错了"区分开）—— V0.1.6 已把它换成真功能。
