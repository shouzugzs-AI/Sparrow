## 1. 汇入 + 重复组内部

### 1.1 组归一化（这一项的关键）

`连接 x t` 只能指到组内**第一份**（`first_of` 的语义），于是"残差前驱"以前只挂在
`t__1` 上，`t__2/t__3` 只有内部链前驱 —— 展开版与循环版会算出**不同的函数**。
现在把第一份"链前驱之外的前驱"复制给组内每一份：

```
t__1 = [链前驱] + 残差
t__k = [t__(k-1)] + 残差        （k ≥ 2）
```

循环版的做法：进位槽就是那条"链前驱"，汇入放在**循环体内**：

```
t__3__l1:
    SHAPE   t__3__m, 1, 4
    EWADD   t__3__m, t__3__in, EMBED_out    ; 进位 + 每圈都参与的残差
    GEMM    t__3_out, t__3__m, t__1_W
    BIAS    t__3_out, t__1_b
    COPY    t__3__in, t__3_out
    LAYERB  t__3__ls
    LOOP_CNT t__3__ctr, @t__3__l1
    LAYERB  t__3__ns
```

`E106` 撤销；播种源必须是 `preds[0]` 的**输出槽**（不是展开版的汇入槽 `<name>_in`
—— 循环版里根本不存在那个槽，这一处写错会让进位槽读到空值）。

### 1.2 验收（`tools/residual_ab.ps1` §7）

| 模型 | 循环版 vs 展开版 | 指令数 | numpy 参考（相对） |
|---|---|---|---|
| 残差在组**外**（12 层） | ✅ **逐字符相同** | 22 < 32 | 1.18e-6 |
| 残差在组**内**（12 层） | ✅ **逐字符相同** | 22 < 54 | 1.32e-6 |

> 与 numpy 参考只做**相对**比较：十几层 GEMM 串联会把 ULP 累积到打印末位
> （相对量级 1e-6）。逐字符那条判据是"两条指令流之间"—— 同一引擎、同一权重，
> 不允许有任何差异。

## 2. 槽位复用

### 2.1 做法

只改"写进哪个槽名"，**不改任何算子、不改常量、不改指令顺序**：

* `last_use[i]` = 最后一个**读** `i` 的层在拓扑序里的位置；被 `前向` 打印的出口槽**钉死**（`usize::MAX`）；
* 一个槽只在"它的最后一个读者处理完之后"才回收（那一层的输入就是它）；
* 池按**输出宽度**分桶：同一个物理槽承载不同宽度会让汇编器为它分配的字节数变化，
  所以只回收宽度完全相同的槽 —— **保守但可证**；
* 循环组不进池（它自己已经把 N 份塌缩成 1 份）。
* 池里存的是**基名**（`slot_base`），真正的槽名是 `<base>_out` ——
  `emit_layer_body` 自己拼 `_out`。（第一版把整名塞进池，结果生成出 `EMBED_out_out`。）

### 2.2 验收（`tools/slot_reuse.ps1`，**从 `.vmb` 的 META 读**）

| 模型 | 槽位 | 激活区 | 输出 |
|---|---|---|---|
| 12 层残差（展开） | 54 → 43 | **1664 B → 960 B（−42.3%）** | 逐字符相同 |
| 最小闭环（链） | 11 → 10 | 256 B → 192 B（−25%） | 逐字符相同 |
| 逐元素尾巴 | 7 → 6 | 320 B → 256 B（−20%） | 逐字符相同 |
| 两/三分支汇入 | 12→12 / 15→15 | 不变（**正确**：分支必须同时活着） | 逐字符相同 |
| 24 层稀疏（循环） | 18 → 18 | 不变（循环版已经塌缩过） | 逐字符相同 |

**can-fail 就在分支模型里**：两个同宽分支必须同时活着才能相加；若生命周期分析
把还活着的槽回收了，汇入会算成 `B+B` 而不是 `A+B`，输出立刻不同 ⇒ 判据 1 会 FAIL。

## 3. 性能

### 3.1 前端：18×（去掉每次关键字分类的堆分配）

`KeywordTable::classes()` 在解析**每个词**时都会跑，而它对**上百个别名**逐个做
`norm(a)`（`to_ascii_lowercase()` = 一次 `String` 分配）。改成逐字节 ASCII 不敏感
前缀比较（`starts_with_norm`，零分配，附等价性证明）：

| 规模 | 之前 | 之后 | 倍率 |
|---|---|---|---|
| 400 层 | 96 ms | 8.7 ms | **11×** |
| 1600 层 | 367 ms | 20.4 ms | **18×** |

`tools/perf_frontend.ps1` 现在把这条**当判据守着**：边际成本 400→800 是
`0.0176 ms/层`，800→1600 是 `0.0183 ms/层`（线性；有二次项的话后一段会爆掉）。
基线（进程启动）~5 ms，所以判据用"去掉基线后的时间"和边际成本，不用绝对比值。

### 3.2 权重精度：bf16 让线性权重与嵌入表**减半**

* `--weight-dtype bf16`：只给 `GEMM` 的 `b`（线性权重）与 `EMB` 的表打上 `:bf16`
  （引擎装载期审计**只**放行这两个位置，偏置/CSR 索引必须保持 f32）；
* 引擎的加宽是精确的（bf16 = f32 高 16 位，`(u32)h << 16`）⇒ 有一条**可判定**的判据：
  A 组（真 bf16）与 B 组（同样数值但以 f32 存）喂给引擎的**位模式完全相同** ⇒ 输出必须逐字符相同。
* 实测：`.vmb` 1104 → **1040 B**；嵌入表 128 → 64 B，线性权重 64 → 32 B；**A/B 逐字符相同**。
* can-fail：拿**未截断**的原 f32 权重跑一遍必须算出**不同**结果（实测不同）—— 证明判据非恒真。
* hard-fail：把 f32 长度的文件标成 bf16 ⇒ 汇编器拒绝且不留产物（元素大小搞错是"第二个元素起全错"那一类）。

> 第一次跑 bf16 验收时输出差了 1.5e-3，看着像"引擎的 bf16 内核算得不一样"。
> 实际是**我自己的参考错**：生成器把 B 组的**所有**常量都截断了（包括 bf16 根本不碰的
> CSR 权重），于是"两组位模式相同"这个前提被破坏。修正后逐字符相同。

### 3.3 激活区：−42%（见 §2）

### 3.4 指令流：循环化 O(1)（见 V0.1.2 报告；本轮补上"残差块也能循环化"）

## 4. 注意力块

### 4.1 展开序列（汇编器里没有 `ATTEN`/`HEAD`，全部自己拼）

```
Q = GEMM(x, Wq) + BIAS bq            ; [T,D]
K = GEMM(x, Wk) + BIAS bk
V = GEMM(x, Wv) + BIAS bv
每头 h（hd = D/H）：
  SLICE   q_h, Q, h*hd, hd           ; 第 4 个操作数是**汇编期专用**的宽度
  SLICE   k_h, K, h*hd, hd           ; （它把 dst 形状钉死，不进 .vmb）
  SLICE   v_h, V, h*hd, hd           ; SLICE 运行时没有任何守卫
  TRANSPOSE kT, k_h                  ; 不能用 RESHAPE（未实现）
  GEMM    s_h, q_h, kT, nn           ; NN：[T,hd]·[hd,T] → [T,T]
  SCALE   s_h, s_h, scale            ; 1/√hd（就地安全）
  SOFTMAX s_h, s_h [, causal]        ; causal 是**裸 flag**
  GEMM    c_h, s_h, v_h, nn          ; [T,T]·[T,hd] → [T,hd]
CONCAT 拼各头 → [T,D]（宽度在长 ⇒ 临时槽 + COPY 左折叠）
GEMM out, ctx, Wo + BIAS bo
```

**为什么不用 `BMM`**：它在 `k==0` 时**整除零 panic**（不是 `exit(9)`），而且完全忽略
`nn`/`acc` flag —— 形状一旦推错就是引擎崩溃而不是报错。

### 4.2 序列长度进架构 IR

任何一层写 `序列=T` ⇒ **模型输入的行数变成 T**（输入激活 `[T,D]`），
注意力于是拿到整段序列。链首限制：`序列>1` 时链首不能是 `嵌入`
（`EMB` 一次只查一个词元 id，产不出 T 行）→ `E107`，**不**静默只算第一个 token。

### 4.3 验收（`tools/attn_ab.ps1`）

| 判据 | 结果 |
|---|---|
| **A 恒等式**：`注意力(T=1)` == 三层线性串联（权重字节完全相同） | ✅ **逐字符相同** `-15.786533 9.903620 11.872891 2.825854` |
| **B1 因果掩码**：`序列=4 因果=是` 时第 0 行 == T=1 结果 | ✅ **逐字符相同** |
| B2 can-fail：`因果=否` 时第 0 行必须不同 | ✅ `-12.084836 5.563807 …` ≠ |
| B3 因果时最后一行 == 不掩码的最后一行（第 3 行本来就能看全部） | ✅ |
| C 注意力放进 `重复2次`（循环版 vs 展开版） | ✅ 逐字符相同（每份实例的缩放常量都复制到位） |
| D1/D2/D3/D4 语义边界 | ✅ `E108` 整除 / `E105` 缺头 / `E108` 真假词 / `E107` 序列+嵌入链首 |

恒等式为什么强：拆头、转置、NN 布局、因果之外的一切**都是纯数据搬运**，
所以"注意力 == 三层线性"这条判据一次性覆盖了切片偏移、头顺序、转置方向、拼接宽度
与输出投影 —— 任何一处接错都会立刻打破逐字符相等。

`[slots] N 个槽位；激活区 B；常量 K 条；文件 B`（**从产物读**，不是生成器自报）。

## 6. 边界与遗留（明确不假装做完）

1. **`--backend lib` 未做**（§7）。
2. 序列 `T>1` 只支持"逐行"链首（`线性`/`归一化`/`激活`）；`嵌入`/`稀疏` 链首 + `T>1` 明确拒绝
   （`E107` / 稀疏层的 CSR 核是向量×矩阵，不吃 T 行）。
3. 注意力的 Q/K 权重不影响 T=1 的结果（softmax 恒等 1）—— 所以 T=1 的恒等式
   验的是**接线**而不是 Q/K 的数值语义；Q/K 的数值语义靠 T=4 的因果/非因果对照间接覆盖。
4. 槽位复用不回收：汇入中间槽 `<name>_in`、循环组的进位/控制槽、注意力内部的
   切头/分数槽（它们与所属算子的生命周期绑定得很紧，回收收益小、风险高）。
5. 多个循环组叠加仍只有单组实测。

## 7. 下一步：`--backend lib`（`.spar → Rust AOT 源`）

设计（可直接开工，但**判据必须先定死**）：

1. `--backend lib --lang rust -o model.rs`：为每个层生成 `struct` + `impl`，
   权重用 `include_bytes!` 内嵌，`fn forward(&self, x: &[f32]) -> Vec<f32>`；
   展开 `.spar` 里那张 DAG（含汇入/注意力/序列），权重布局与 `.args` 一一对应；
2. **判据必须先想清楚**（这是本轮侦察的结论，不是细节）：引擎的 `gemm_nt` 走
   **AVX2 + FMA + 8×8 分块**，bf16 又是另一套**双累加器**内核 —— 实测过：纯 numpy
   参考（无论四舍五入还是 longdouble-FMA 模拟）都差 1 ULP。所以"生成的 Rust 用朴素
   循环 ⇒ 与 `.vmb` 逐字符相同"**做不到**。两条路线必须**二选一**并写进报告：
   * **(a) 链接同一套内核**：生成的 Rust `use vmlm_ops::kernels::gemm_nt;`，
     算术完全一致 ⇒ **逐字符相同**可达（代价：产物不再零依赖）；
   * **(b) 接受 ULP 容差**：判据改成"相对误差 ≤ 1e-6，且 can-fail 量级 ≥1e-1"，
     并**明确写清**这不是逐位一致（与 V0.1.2 报告里对 `loss_hash` 的处理同一种诚实）。
3. can-fail：故意把某个层的权重索引错一位 ⇒ 输出必须变化；
4. 为什么它算性能项：AOT 路径没有解释器的逐指令分派，是「产物侧」的最后一个大杠杆
   （bf16 已经把权重字节减半，槽位复用已经把激活区压到 −42%）。
