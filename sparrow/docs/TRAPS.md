# Sparrow 已知陷阱（V0.1 → V0.1.5 累积）

> 每条都是**实际踩过并复现过**的，不是"注意事项"式的泛泛之谈。
> 格式：现象 → 根因 → 对策（代码里落在哪）。
> 分组：**73 条**：A 工具链/进程/基准(15) · B 汇编器契约(11) · C 前端语法/诊断(8) · D 构建约定(2) · E 循环化(13) · F 注意力/序列(6) · G Rust 后端/量化/槽位/训练(13) · H 仓库/版本化(3) · I 槽位复用(2)
> 其中 V0.1.6 新增：**C8**（关键字别名当实例名）、**G10**（注意力每头暂存槽）、
> **G11**（`MSE_BWD` 操作数顺序 + 官方运行时不带 train feature）、**G12**（反向与复用/循环互斥）、
> **H3**（`.gitattributes` 不回溯改写已入库的 CRLF）。

## A. 工具链 / 进程 / 环境

### A1. Windows PowerShell 5.1 按 ANSI 读无 BOM 的 `.ps1`
- **现象**：脚本里中文全变 `寮曟搸` 之类乱码，随后报 `Unexpected token`、`Missing closing '}'`
  ——看起来像语法错误，其实是编码。
- **根因**：`.ps1` 没有 UTF-8 BOM 时，Windows PowerShell 5.1 用系统 ANSI 代码页解码。
- **对策**：写脚本时加 UTF-8 BOM，并用 `pwsh`（PS7）执行：
  ```powershell
  [System.IO.File]::WriteAllText((Resolve-Path $p), $s, [System.Text.UTF8Encoding]::new($true))
  pwsh -NoProfile -ExecutionPolicy Bypass -File tools/e2e_tiny.ps1
  ```

### A2. `Select-Object -First N` 会掐断上游管道、污染 `$LASTEXITCODE`
- **现象**：测汇编器退出码时读到 `exit=`（空）或错误的负值；换个命令又正常。
- **根因**：`-First N` 满足后 PowerShell 停止读取并**终止**上游进程；退出码反映的是这次终止。
- **对策**：先完整消费输出再取码：
  ```powershell
  $o = & $asm @args 2>&1 | Out-String
  $c = $LASTEXITCODE
  ```

### A3. 汇编器失败是 `panic=abort`：退出码是负数，`u8` 装不下
- **现象**：`vmlm-asm.exe` 遇到未知指令/未实现指令/读不到权重时退出码 `-1073740791`
  （`0xC0000409`），stderr 是 `thread 'main' panicked at …`，**且不产出 `.vmb`**。
- **根因**：release 配置 `panic=abort`，abort 的 NTSTATUS 被解释成 i32。
- **对策**：转发必须走 `std::process::exit(i32)`；用 `ExitCode::from(u8)` 会把
  `-1073740791` 截成 `153`，脚本再也分辨不出失败类型。成功路径另加一条
  "退出码 0 但没产出 `.vmb`" 的矛盾态拦截（`E202`）。

### A4. 子进程的 CWD 变了 ⇒ 相对路径的基准也变了
- **现象**：`--asm` 把汇编器 CWD 设成常量目录后，传相对的 `.vml` 路径 → 汇编器报
  `读不到 .vml: NotFound`（它只说不存在，不说基准变了）。
- **对策**：`.vml`/`.vmb`/CWD 一律转**绝对路径**（`abs_path`，不 canonicalize，
  以免要求文件已存在）；权重清单里的 `.bin` 保持相对（就是要按 CWD 解析）。

### A5. 引擎写死读 `model.vmb`（相对路径）
- **现象**：直接 `vmlm-runtime.exe <某个.vmb>` 不行；换目录跑报 `exit=2 cannot open file`。
- **对策**：把 `.vmb` 拷成 `target\release\model.vmb`，并以该目录为 CWD 运行。

### A6. 汇编器命令行必须带全部权重
- **现象**：不给 `name:file:rows:cols` 也能"成功"，但引擎算出来是垃圾 ——
  汇编器只打印 `⚠️ 警告：0 个常量`。
- **对策**：Sparrow 的 `--backend vml` 同时产出 `.args` 清单；`--asm` 模式自动带上。

### A7. 引擎的 `print_f32` 是**截断**，不是四舍五入 ⭐
- **现象**：numpy 独立算出的参考值与引擎输出**每个数都差 1 个末位**，
  而且是单向的（引擎的绝对值总是更小）。V0.1.1 的 e2e 报告里
  "numpy `0.975112` / 引擎 `0.975111`"这条差异一直没解释，就是它。
- **根因**：`core/src/interp.rs:2459-2468` 逐位取小数：
  `frac *= 10.0; let dig = frac as u32; frac -= dig as f32;` —— **从不进位**。
- **对策**：参考实现必须**复刻这个格式**（`tools/gen_residual.py::eng_fmt`），
  复刻之后比较就是**逐字符**的（容差比较会放过真实的算子错误）。
  复刻后 `residual_*`/`loop24` 的参考值与引擎输出**逐字符相同**。

### A8. 用 `.cmd`/`.ps1` 当"假汇编器"接不上 fork
- **现象**：想用脚本包装汇编器做故障注入，但 `--asm` 只接受**一个可执行路径**，
  `--asm "python x.py"` 不会被拆成两个参数。
- **对策**：故障注入器编成真 `.exe`（`examples/asm_fault_inject.rs`，
  `cargo build --example asm_fault_inject`），它读环境变量决定注入什么故障 ——
  这样**不改真实汇编器**也能端到端验 `E210`。

### A9. `($x | Where-Object {...})[0]` 在**只匹配一条**时取到首字符 ⭐
- **现象**：探针脚本要照抄 vmlm 的 `members = [...]` 行，生成的父仓库 `Cargo.toml`
  里那一行变成单个字母 `m`，cargo `exit=101`，三条判据全红（**假失败**）。
- **根因**：PowerShell 的管道在只产出一个对象时把它解包成**标量**；
  对标量取 `[0]` = 取第一个字符。`@(...)` 才会固定住数组类型。
- **对策**：`$line = @($text -split "`n" | Where-Object { $_ -match '^members\s*=' })[0]`
  —— 凡「过滤后取第 N 条」都要显式 `@()`；同类还有 `(Get-ChildItem ...).Count`。
- **判据写法提醒**：这类错误**看起来像被测系统坏了**。探针里判据 3（can-fail 那一条）
  正是用来区分「被测系统坏了」与「我的脚本坏了」的：去掉 `[workspace]` 后
  cargo 的报错文本（`believes it's in a workspace when it's not`）与脚本 bug 的
  报错文本（`failed to parse manifest`）完全不同。

### A10. 引擎的 `print_f32` 会把 **NaN 洗成 `0.000000`** ⇒ 判据可以双双恒真 ⭐⭐
- **现象**：基准跑出"引擎输出 == AOT 输出"**PASS**，同时 can-fail（"改权重输出必须变"）**FAIL** ——
  两边的输出都是 `0.000000 0.000000 …`。
- **根因**：`print_f32`（`core/src/interp.rs:2416`）是**截断**实现：`let ip = av as u64;`
  —— `NaN as u64 = 0`，`frac` 也是 NaN ⇒ 逐位取到的都是数字 0。于是 **NaN 被打成合法数字**。
  而候选模型是 96 层未归一化的随机正态权重：每层增益 ≈ 谱半径 2 ⇒ 2^96 ⇒ 全 NaN。
- **后果**：这类"输出退化"会让**正确性判据与 can-fail 判据同时失去判别力** ——
  单看那两条会以为验过了。
- **对策**（两层都要）：
  1. 判据里加**退化守卫**：输出的"互不相同值个数"必须 > D/2（以及个数 == D）；
  2. 生成器加**数值自检**：输出必须全有限、不退化、且"扰动一个权重必须让输出变 >1e-3"。
  实测修复：权重按**行 L2 归一化**（每层保范），`max|y|` 从 NaN 变成 9.5/22/23。

### A11. Python 子进程的中文输出在 pwsh 里乱码
- **现象**：`& python tools\gen_bench.py …` 打出来的是 `Ȩ�� 18 ���ļ�` 这种乱码。
- **根因**：子进程按一套编码写（PYTHONIOENCODING / 控制台代码页），PowerShell 按另一套解码。
- **对策**：脚本开头两边都钉死：
  ```powershell
  $env:PYTHONIOENCODING = "utf-8"
  try { [Console]::OutputEncoding = [System.Text.Encoding]::UTF8 } catch { }
  ```

### A12. 基准的"每层成本"**不是常数**；负截距是"模型不合适"，不是"固定开销为负"
- **现象**：用 N=8/32/96 三个点做两参数线性拟合，得到 `31.4 µs/层 + 固定 -97.5 µs`
  —— 截距为负。
- **根因**：权重从 2.1 MB（命中缓存）涨到 25.3 MB（越过 L3）后，每层成本**上升**
  （实测 26.3 → 32.9 µs/层）。线性模型不成立时，斜率与截距都没有物理意义。
- **对策**：报**分段边际成本**（相邻两点之差 / ΔN），并显式标注"截距为负 ⇒ 线性模型不合适"；
  任何"每层成本"的主张都要带上权重体积与缓存状态。

### A13. PowerShell 里范围 `..` 的优先级**低于** `*` ⇒ 必须先给起始下标加括号
- **现象**：写 `$vals[$k * $dim..($k*$dim+$dim-1)]`，报
  `Method invocation failed because [System.Object[]] does not contain a method named 'op_Multiply'`
  —— 看起来完全不像数组下标的问题。
- **根因**：`..` 比 `*` 松，表达式被解析成 `数组 * (整数..整数)`。
- **对策**：`$vals[($k*$dim)..(($k+1)*$dim-1)]`，或封成 `RowOf $vals $k $dim` 这样的函数。

### A14. 改了输入常量 `.bin` 之后**必须重新汇编**（`.vmb` 把常量烧进去了）
- **现象**：A/B 对照"逐个词元跑 T=1 模型"，三次得到的都是同一个词元的输出 ——
  看起来像"输入没生效"，其实是产物没重建。
- **根因**：常量（含模型输入）在汇编期就**内嵌进 `.vmb`**；改 `.bin` 不会改已有产物。
- **对策**：改完 `.bin` 立刻重跑 `--asm`/`ASSEMBLE` 再执行（`tools/seq_ab.ps1` 第 1 节就是这么修的）。
  同族：`.vmb` 也不读任何外部权重文件。

### A15. 前端自产的极小常量默认落在**进程 CWD** ⇒ 会把调用者的目录弄脏
- **现象**：跑完验收后仓库根多了 4 个文件：`ATTN_scale.bin`、`t__1_{iters,lstride,nstride}.bin`。
  它们不是驱动显式写的，而是前端"自己产出的常量"。
- **根因**：`--backend vml` 且**没给** `-o`/`--args` 时，兜底目录是 `.`（进程 CWD）。
  验收驱动的负例正是这么调的（只想要 stdout），于是往调用者的当前目录丢文件 ——
  而 `verify_all.ps1` 的 G1（跑完 `git status` 必须为空）会把它抓出来。
- **对策**：兜底锚定改成 `--args` 目录 → `-o` 目录 → **输入源码所在目录** → `.`；
  驱动侧一律显式给 `-o`（`tools/attn_ab.ps1` 的负例已改）。
  教训：**"没有输出路径时写哪里"必须是一个确定且与本次编译相关的锚**，
  不能是"调用者碰巧在哪"。

## B. 汇编器（`.vml`）契约

### B1. `;` 是注释；`.` 开头的行被整行跳过
- `.section forward` 是**纯装饰**（汇编器直接跳过），保留只是为了与既有示例一致。
- 标签写法是**单独一行** `name:`，跳转写 `@name`。

### B2. 用了 `UNIMPLEMENTED_OPS` 里的指令 = 汇编期硬失败
- 清单：`LOADK` `RESHAPE` `MEAN` `NORM` `GATHER` `SCATTER` `BRANCH` `OP_CALL`。
- 想让 `SPARSE_MATVEC` 的列向量输出变成行向量时，**`RESHAPE` 用不了**，要 `TRANSPOSE`。

### B3. `EMB` 没有形状推断 ⇒ 必须显式 `SHAPE`
- 不写 `SHAPE`，输出槽停在 `0x0`：引擎要么报错、要么**静默不写**。

### B4. `bias=<slot>` 融合 flag 会**丢掉槽位名**
- 汇编器对 `key=value` 只取 `key` 当 flag，`value` 被丢弃 ⇒ 偏置槽落成 0 ⇒ 读 slot0 垃圾。
- 对策：写两条指令 `GEMM` + `BIAS`（仓库里所有真实示例都是这么写的）。
- **补充（V0.1.2 核实）**：`bias`/`bc`/`neg` 这三个 flag 在 `interp.rs` 与
  `ops/*.rs` 里**一次都没被读过**（grep 零命中）—— 它们是"编进去了但没人用"的死位。
  唯一被读的是 `FL_TRANS_B`(tb/nn)、`FL_ACC`、`FL_CAUSAL`、`FL_NNZ`、`FL_SELGATE`。

### B5. `SPARSE_MATVEC` 的形状契约（引擎侧硬守卫，不是建议）
```
SPARSE_MATVEC dst, offsets, src, w, x [, nnz]
  offsets  必须是 [n+1, 1] 列向量
  src      必须是 [nnz, 1] 列向量
  dst      dc == 1 且 dr >= n（列向量！）
  语义：dst[j] = Σ_{t: offsets[j] ≤ t < offsets[j+1]} w[t] * x[src[t]]
```
- `offsets`/`src` 都是 **f32 存整数**（引擎读 `*co.add(j) as usize`）。
- `nnz` flag 会把实际乘加次数写进 `dst[n]`（验收仪器，生产路径别开）。
- 行内列号**必须递增**，否则 CSR 的累加顺序与稠密参考不同 ⇒ "逐位比较"会假失败。

### B6. `st_` / `g_` 是保留的槽位名前缀
- `st_` = 持久状态槽、`g_` = 梯度槽。普通激活槽撞上这两个前缀会被解释成别的种类。

### B7. 槽位名/常量名在符号表与命令行里按**字节**走
- 中文名没有收益只有风险（编码、排序、工具链）。生成器把非 ASCII 名换成
  `<小写层类型><序号>`。

### B8. `@name` **只**是跳转标签 ⭐
- **现象**：写 `COPY ctr, @t_iters`（想"从常量取初值"）→ 汇编器 panic
  `指令 COPY 不支持跳转标签（@...）。只有 JMP / BRANCH / CMPLE / LOOP_CNT 需要标签。`
- **根因**：操作数扫描**先**把 `@xxx` 抽成标签，再按 opcode 校验是否允许标签。
- **对策**：常量槽直接写名字：`COPY ctr, t_iters`。
  全仓库里 `@` 只允许出现在 `LOOP_CNT ctr, @label` 的目标上（有回归测试守着）。

### B9. `SPARSE_MATVEC` 的权重槽号必须 ≤ 63 ⇒ **展开版 21 层就装不出来** ⭐⭐
- **现象**：`重复24次` 的**展开**版汇编失败：
  `SPARSE_MATVEC 的权重槽号 66 超过 fl 低 6 位的上界 63`。
- **根因**：这条指令的第 4 个槽被压进 `fl` 的**低 6 位**（`SPARSE_WSLOT_MASK`），
  而槽号是**绝对索引**。展开版每层 3 个常量槽 ⇒ 第 21 层的权重槽号就 > 63。
- **对策**：这正是循环化（`--loop-repeat`）的真正价值 —— 循环版只引用**第 1 份**常量，
  槽号恒定 18 个，于是**层数再多都能装**。所以对 ≥21 层的稀疏模型，
  循环化不是优化，而是**唯一可行的编译路径**。
  （反过来说：`重复 N` 展开路径的可用上限是 ~20 层，别拿它当"对照的黄金标准"。）

### B10. 汇编器几乎**不检查操作数个数**；缺的操作数静默变 slot 0
- 通用路径是 `regs.first()/get(1)/get(2).unwrap_or(0)` ⇒ 少写一个操作数 =
  悄悄引用 slot 0（而 slot 0 往往是个合法的激活槽）⇒ **数值静默错**。
  `max_operands()` 定义了但**从未被调用**（死代码）。
- **对策**：前端发指令时**逐条**写全操作数；`BIAS dst, bias` 是两条操作数，
  `LN dst, src, gamma, bias` 是四条（偏置走 `dt` 字段，不是 flag）。

### B11. `SLICE` / `CONCAT` / `MASK_MUL` **没有任何运行时形状守卫** ⭐
- `SLICE dst, src, off, width`：第 4 个操作数是**汇编期专用**（把 dst 形状钉死），
  不进 `.vmb`；运行时按 dst 的列宽写，`off + dc > src 列数` 时**读穿到相邻槽**。
- `CONCAT dst, a, b`：dst 的行跨步被写死成 `ac+bc`，**不检查** `dc == ac+bc`，
  也不检查 `rows(b) == rows(a)`。
- `MASK_MUL dst, a, mask`：列数取自 **dst**，mask 长度不检查；dst 0x0 ⇒ 静默空转。
- **对策**：前端**必须**自己把形状写对（我们一律显式 `SHAPE` 汇入/中间槽），
  并且不能依赖"引擎会报错"。对照：`TRANSPOSE` 有面积守卫、`EW*` 有形状守卫(exit 8)、
  `BMM` 甚至会在 `k == 0` 时**整除零**直接 panic（不是 exit(9)）。

## C. 前端（Sparrow 语法）

### C1. 单字母关键字别名会吞标识符
- `M`=model、`L`=layer、`x`=repeat 是第九部分明列的别名，因此 `模型 m:` 报 `E007`，
  **`l`** 也是保留的（layer）—— 测试里给层起名要避开 `m`/`l`/`x`/`t`/`o`/`e`。
- 前缀匹配因此加了闸：中文 ≥1 字、ASCII ≥3 字符（否则 `e`/`t`/`o` 会被
  `end`/`then`/`op` 吞掉）。

### C2. 层类型只精确匹配（不做前缀）
- 否则验收 11 的 `Spars` 会被当成合法的 `Sparse`，"未定义的层类型"永远报不出来。

### C3. `。` 是分隔符，不是块结束标记
- 第四部分说中文标点"只作为分隔符"，第九部分却把 `。"` 列在 `end` 类；取第四部分。

### C4. 中文数字只在"数字位置"转换
- `二十四` 是字母，词法层不能拆（拆了 `一致`/`一年` 就碎了）。
- `重复 二十四 次` ✅、`重复24次` ✅、`重复二十四次`（全无空格）❌。

### C5. 中文复合连接词只在"期待关键字的位置"切分
- `连到`=`连`+`到`、`前向到`=`前向`+`到`；不能放进 lexer，否则 `嵌入层` 也被切成
  `嵌入`+`层`（而四/七部分要求它是一个标识符）。

### C6. 一个层被多条 `连接` 指到 = **汇入**（V0.1.3 起合法）
- 这是**故意**用既有语法承载新语义：不需要新关键字，符合"任何符合逻辑的写法都接受"。
- 合流方式：等宽→相加(`EWADD`)、不等宽→拼接(`CONCAT`)；
  也可用 `合并=相加|拼接`（别名 `汇入`/`合流`/`残差`/`merge`/`residual`…）显式指定。
- **前驱顺序 = `连接` 语句出现顺序**：相加可交换所以无感，**拼接不可交换**所以是语义。
- 这一层**不能**再写与汇入宽度矛盾的 `输入=`（报 `E100`）。

### C7. 「语言还没有的功能」要报成**语义边界**，不能报成"你打错了" ⭐
- **现象**（V0.1.5 之前）：写 `反向` 报 `E002 未定义的层类型 "反向"`；写 `损失 均方` 报
  `E006 连接/前向引用了未定义的层 "损失"`。两条都在暗示用户拼错了 —— 而真实原因是
  **本语言没有损失/反向陈述**（引擎侧那 10 个反向/优化算子早就有了）。
- **代价**：误导性诊断把人引向"改拼写"的死路；本项目"暂不合并外部 PR"，
  等于把唯一的信息渠道浪费掉。
- **对策**：维护一张**训练词表**（`keywords::training_word`），在 `parse_stmt` 最前面精确匹配
  ⇒ 报 **`E111`**，提示里点明缺的是语言表达层，并列出引擎已有的算子。
  两条 can-fail 守着不误伤：真拼错的层类型仍 `E002`（带建议）；
  `训练 = 线性 …` 这种"当实例名"的写法照常编译。

## E. 循环化（`重复` → `LOOP_CNT` + `LAYERB`）

### E1. `LAYERB` 的增量是 **f32**，被 `as usize` **向零截断**（不是"有符号字节"）
- `interp.rs:1036-1042`：`d0 >= 0.0 ? base += d0 as usize : base -= (-d0) as usize`。
- 于是**非整数步长会被静默截断**，从第 2 层起读错权重而且不报错；
  NaN 走负数分支、`(-NaN) as usize` 饱和成 0 ⇒ base 不动，**也是静默的**。
- **对策**：前端硬校验步长能被 f32 精确表示（`E212`）。步长是 64 的倍数且 < 2^30 时必然成立。
- 实测 MiniCPM 的 28,383,232 B 步长正好精确（15 位有效位）。

### E2. `LAYERB`/`LOOP_CNT` 的操作数槽必须是**激活槽**，不能是常量槽 ⭐
- 两者都经 `slot_mut` → `const_ptr` 读值，而 `const_ptr` 会**加上 `layer_base`**。
  用常量槽做计数器/步长 ⇒ 第 2 圈开始读到被平移过的值 ⇒ 静默错。
- **对策**：`SHAPE x_ctr, 1, 1` + `COPY x_ctr, <常量>`（循环**外**做一次），
  循环体里只用激活槽。回归测试守着"计数器/步长槽必须先 SHAPE"。

### E3. 循环体里**不能**出现非 per-layer 的常量访问
- `layer_base` 是**在常量访问时**统一加上的，不区分"这份常量属于谁"。
  模型输入/词元 id 这类共享常量若在循环体内被读，会被一起平移。
- **对策**：循环的输入一律先 `COPY` 进**激活进位槽**（循环外播种），
  循环体只读这个进位槽 + 自己的 per-layer 常量块。

### E4. 收尾还原要减 **N×步长**，不是 1×步长
- N 圈各推进一次 ⇒ 循环结束时 `layer_base = N*stride`，
  循环后的常量访问（最终 norm 等）必须回到 0。写成 `-stride` 会让后面整片错位
  （而且因为 `const_ptr` 的越界检查只在**越界**时才 exit(9)，小偏移会静默错）。

### E5. `LOOP_CNT` 是**减完再判**；`ctr` 必须是 `[1,N]`
- 初值直接写 N（`nv = *ctr - 1; if nv > 0 { ip = d }`），目标必须**向后**。
- 汇编器还会硬校验"循环体内没有别的指令写计数器槽"（防每圈减 2）。

### E6. 步长必须**实测**，不能只靠前端复刻 `CONST_ALIGN`
- 常量池的布局（按 argv 顺序、每块补齐到 64）是汇编器的实现细节；
  前端复刻一份"预测值"是可以的（`--backend vml` 模式下没有汇编器可读），
  但**一旦汇编出 `.vmb` 就必须拿 META 常量表对账**（`E210`）：
  1. 池序 = 清单序（逐条比 `rows/cols/len`）；
  2. 相邻两份的偏移差**恒定**；
  3. 实测步长 == 预测步长。
- 对账失败 ⇒ **删掉产物**再报错，绝不留下一个"步长未知"的 `.vmb`。

### E7. 判据必须是"与展开版逐字节相同"，而且**每层权重必须不同** ⭐
- 步长错一位时**第 1 层仍然正确**，从第 2 层起静默错。
  若 24 层用同一套权重，"逐字节相同"这条判据**恒真**，等于没验。
- **对策**：生成器给每层一个不同 seed 并断言两两不同
  （`tools/gen_loop24.py`）；再配 can-fail：步长 ±64/±192 后输出**必须**变化
  （`tools/loop_ab.ps1` §4，实测引擎 exit=9 且输出不同）。

### E8. 重复组内每一份的**前驱结构必须一致**（V0.1.3）
- `连接 x t` 只能指到组内**第一份** ⇒ 残差前驱以前只挂在 `t__1` 上，
  于是展开版（只有第一层汇入）与循环版（每圈都汇入）算出**不同的函数**。
- **对策**：把第一份"链前驱之外的前驱"复制给组内每一份
  （`t__k = [t__(k-1)] + 残差`），循环版把进位槽当那条链前驱、汇入放进循环体。
- 播种进位槽的来源必须是 `preds[0]` 的**输出槽**：写展开版的汇入槽
  `<name>_in` 会读到循环里根本不存在的槽（实测输出差到 1e-1 量级）。

### E9. 每份实例的**前端自产常量**也要按实例名复制
- 注意力自己会产出一个缩放常量（`1/√hd`）。循环化时每份实例的常量块名不同
  （`a__1_*` / `a__2_*`），若只复制 `ConstDecl` 而不复制那份 `.bin`，
  第 2 份的 `LAYERB` 走过去会**读不到文件**。
- **对策**：`emit_loop_group` 里把 `bins` 一并按实例名前缀复制
  （`tests/attention.rs::attn_inside_repeat_gets_per_instance_scale_bins` 守着）。

### E10. `Layer::group` 是**每层自增的计数器**，不是循环组编号 ⭐
- **现象**：给 `Plan` 加循环组投影时，用 `layers[j].group == g`（g 遍历 `loop_groups` 下标）
  取成员 —— 结果把**非 `重复` 的层**也当成组员（`n_groups` 对每个层都自增，`n=1` 也会拿到一个 group 值）。
- **根因**：`Layer::group` 的语义是"这个层属于第几个 `CItem::Layer`"，只有同一次 `重复`
  展开出来的几份才共享它；它跟 `LoopGroup` 在 `Vec` 里的位置**没有关系**。
- **对策**：用**模板实例名**（`LoopGroup::cprefix`，如 `t__1`）先定位到那一层，再取它的
  `group` 值当组号（文本后端本来就是用 `l.group` 取成员的，两边于是同源）。
  写代码时顺手 `debug_assert_eq!(insts.len(), iters)`。

### E11. 源层的 `重复` 会**越界 panic**，必须换成命名诊断 ⭐
- **现象**：`嵌入 词表=8 维度=4 重复3次`（链首、没有前驱）配上 `--loop-repeat`，
  前端直接崩：`panicked at src\vmlgen.rs: index out of bounds: the len is 0 but the index is 0`。
- **根因**：循环体要播种进位槽，源码写死用 `l.preds[0]` 当链输入；源层的 `preds` 是空的。
- **对策**：`--loop-repeat` 且这一层是组内第一份、`preds` 为空时返回 **`E110`**
  （带位置与 caret + 提示"加 `连接` 或去掉 `重复`"）；展开模式不受影响。

### E12. `序列=T>1` + 循环组：进位槽行数写死成 1 ⇒ **静默只算第一行** ⭐⭐⭐
- **现象**：`线性 输入=4 输出=4 序列=3` + `重复2次` 配 `--loop-repeat`，
  输出**只有 4 个数**（应当 12 个：3 行 × 4），**退出码 0**，没有任何告警。
- **根因**：循环发射里两张写死的 `SHAPE`：进位槽 `SHAPE <last>__in, 1, in_cols`、
  汇入槽 `rows=1`。循环体内的 `GEMM` 的 `m` 取自**输入槽形状** ⇒ 只算 1 行，
  组的输出槽变成 `[1,4]`，`PRINT` 就只打一行。
- **为什么这是最坏的一类**：不报错、不崩、悄悄少算 —— 本项目把"静默降级"列为头号禁止项。
- **对策**：把 `t_seq` 传进循环发射，进位槽/汇入槽都按 `[T, D]` 声明
  （`.vmb` 槽表里应为 `t__2__in [act] 3x4`）；并把它做成**常驻判据**：
  `examples/seq_loop.sparrow` + `tools/seq_ab.ps1` §6「循环版 == 展开版（逐字符）」。

### E13. `序列=T>1` 时**非逐行算子**必须硬拒绝，不能放过去
- **现象**：`SPARSE_MATVEC` 是**向量×矩阵**（`[D,1] → [D,1]`），一次只吃一行；
  链路中间的 `嵌入`（输入已经是 `[T,D]`）同理。放进 T>1 的链路里，它们同样**只算第一行**。
- **对策**：`t_seq > 1` 时对这两个情形直接报 `E107`（带理由），而不是让它跑出一个错答案。
  逐行算子（`线性` / `归一化` / `激活` / `注意力`）不受影响；`嵌入` 作为**链首**是允许的
  （V0.1.5 起走"逐行查表 + 拼行"，见 REPORT_V015 §5）。
  教训：**"上游保证不会发生"的假设要在入口写成诊断**，不能让它变成 `[]` 索引。

## F. 注意力块 / 序列长度（V0.1.3）

### F1. 汇编器里**没有** `ATTEN`/`HEAD`/`SELGATE` 这类助记符
- 76 个助记符里 grep 不到；注意力必须自己用
  `GEMM/SLICE/TRANSPOSE/SCALE/SOFTMAX/CONCAT` 拼出来（见 `emit_attn`）。

### F2. `SLICE` 的第 4 个操作数是**汇编期专用**的宽度，运行时又没有守卫 ⭐
- `SLICE dst, src, off, width`：`off` 是数字（进 `b`），`width` 只在汇编期把 dst 形状
  钉死（`force_shape`），**不进 `.vmb`**；运行时按 dst 的列宽逐行拷贝，
  `off + dc > src 列数` 时**读穿到相邻槽**，没有任何检查。
- **对策**：拆头时显式写 `SLICE q_h, Q, h*hd, hd`，并保证 `Q` 的行宽确实是 `H*hd`。

### F3. `SOFTMAX` 的行宽取自 **dst**，`causal` 是裸 flag
- `SOFTMAX dst, src [, causal]`：先 `copy a→d`，再按 **d 的** (r,c) 做行 softmax；
  causal 时 `lim = 行号+1`，并把 `[lim, 列数)` **显式清零** ⇒ 正好是下三角掩码。
- 推论（本轮的验收基石）：**第 0 行只有一个元素参与 ⇒ softmax ≡ 1**，
  所以 `序列=1` 的注意力恒等于 `Wo·(Wv·h + bWv) + bWo`。
  这条恒等式把"拆头/转置/拼接/输出投影是否接对"变成**逐字符可判定**。

### F4. `BMM` 不能用（宁可自己拼 `GEMM ..., nn`）
- `BMM` 在 `k==0` 时做整数除法 `bk/k` ⇒ **panic**（不是 `exit(9)`）；
  而且它**完全忽略** `acc`/`nn` flag（汇编器却接受这些 flag）。
- **对策**：批量矩阵乘一律 `GEMM dst, a, b, nn`（`nn` ⇒ N 取 `cols(b)`）。

### F5. 序列进 IR ⇒ 输入激活是 `[T,D]`；`EMB` 一次只查一行
- 任何一层写 `序列=T` ⇒ 模型输入常量变成 `[T,D]`（否则注意力拿不到序列）。
- `EMB dst, table, row` 的 `row` 是**一个** f32 标量 ⇒ 序列 >1 时它产不出 T 行。
- **对策**：`序列>1` 且链首是 `嵌入` ⇒ `E107` **明确拒绝**，
  不静默只算第一个 token（那是最坏的一类静默降级）。

### F6. `causal` 的值必须是"真假词"，不能猜
- `因果=或许` 这种写法如果被静默当成"不掩码"，就是**静默算错模型**。
- **对策**：`attr_flag` 只认 是/真/1/true/yes… 与 否/不/0/false/no…，
  其它一律 `E108` 并给候选。

## G. Rust AOT 后端（`--backend lib`，V0.1.4）

### G1. 朴素循环的 GEMM **无法**与 `.vmb` 逐字符一致 ⭐⭐
- 引擎的 `gemm_nt` 是 AVX2 + FMA + 8×8 分块，bf16 又是另一套双累加器内核；
  实测纯 numpy 参考（四舍五入**和** longdouble-FMA 模拟）都差 **1 ULP**，
  而那 1 ULP 会翻掉打印的第 6 位小数。
- **对策**：生成的 Rust 直接 `use vmlm_ops::kernels::*` 调**同一个函数**；
  逐元素/搬运算子（BIAS/SCALE/TRANSPOSE/SLICE/CONCAT/EWADD）按 `interp.rs`
  的同一条标量规则手写；稀疏的 CSR 累加在 `interp.rs` 里本来就是标量循环
  （`acc = term` 首项 / `acc += term`），照抄即逐位一致。
- 代价必须写清楚：**产物不再零依赖**。换来的是"逐字符一致"这个**可判定**判据 ——
  比"相对误差 ≤1e-6"强，容差会放过真实的算子错误。

### G2. 生成在宿主仓库目录里的 crate 必须声明 `[workspace]`
- **现象**：`cargo run --manifest-path out/lib_e2e/Cargo.toml` 报
  `current package believes it's in a workspace when it's not`。
- **根因**：`out/` 在 sparrow 仓库里，cargo 沿父目录找到了 `Cargo.toml`。
- **对策**：生成的 `Cargo.toml` 里加一个空的 `[workspace]` 表，明确"我是独立包"。

### G3. 别把 build 的 warning 混进"被比较的字符串" ⭐
- **现象**：Rust 后端的 6 项验收**全部**假失败，输出里是
  `warning: unused doc comment` —— 而不是程序的输出。
- **根因**：用 `cargo run --quiet 2>&1 | Out-String` 抓输出，编译器的 stderr 被
  一起抓进来了。
- **对策**：先 `cargo build`（把输出丢掉），再**直接跑产物**取 stdout。
  （与 A2「`Select-Object -First` 污染 `$LASTEXITCODE`」是同一族错误：
  **抓输出的方式本身会污染判据**。）

### G4. `EMBED` 的 `in_dim` 是 0（它的输入是词元 id，不是激活向量）
- **现象**：生成代码里 `assert_eq!(x.len(), rows * ind)` 立刻 panic（`left: 1, right: 0`）。
- **对策**：生成端按层类型给输入宽度：`EMBED` → 1，其余 → `in_dim`。

### G5. `HashMap` 索引在表达式位置是**值语义**
- **现象**：`merge_add(&[slots["a"], slots["b"]], ..)` 报
  `expected &Vec<f32>, found Vec<f32>`（试图移动）。
- **对策**：显式取引用 `&slots["a"]`。

### G6. Rust 版循环组**不能**照搬 `LAYERB` 的思路 ⭐
- **现象**：想让 Rust 也"一份代码 + 平移常量基址"，但 Rust 没有可平移的常量池指针：
  `include_bytes!` 出来的是各自独立的 `static`。
- **对策**：Rust 侧改成**按实例内嵌常量 + `for` 循环**：
  `struct G0Inst { … }`（一份代码）+ `G0 { items: Vec<G0Inst> }`（N 份常量），
  循环体 `carry = inst.forward(&carry, rows)`。语义对齐见 REPORT_V015 §3.2。
- 同时：`<前缀>_iters/_lstride/_nstride` 三个常量是 `LAYERB` 的**实现细节**，
  Rust 版必须**跳过**它们（否则生成未使用的 `static`，还会让人以为要复刻步长）。

### G7. 同一份 `forward` 代码要挂在两种承载上 ⇒ 生成器必须拆成"字段/正文"两半
- **现象**：`layer_struct` 原来把字段声明、`new()`、`forward` 拼在一个函数里；
  循环组需要"N 个实例共用一份 `forward`"，直接复用就变成 N 份代码，循环化白做。
- **对策**：拆成 `fields_of()`（字段声明 + 初始化表达式）与 `forward_fn()`（含签名的正文），
  两者各自可复用；`layer_struct` 与 `group_struct` 只是不同的拼装方式。

### G8. int8 的判据**不能**照搬 bf16 的"与 f32 逐字符相同" ⭐
- **背景**：`gemm_nt_int8` 与 `gemm_nt` 是**两个内核**：前者 8 宽单行 FMA + 尾部标量、`scale` 乘在
  内积**之外**；后者 AVX2 8×8 分块。累加顺序不同 ⇒ 即使权重可被 int8 精确表示，和也可能差 ~1 ULP。
- **对策（三档判据）**：
  1. **k=1**（输入宽度 1，内积一项）取 `scale = 2⁻⁶`、`w = q/64`（精确可表示，且乘 2 的幂与舍入
     可交换）⇒ 两条路必须**逐字符相同**（这条能抓住行列布局 / scale 取错行 / bias 位置错）；
  2. **k>1** 只要求差值 ≤ 界，并**打印实测值**；
  3. **can-fail**：把某一行的 scale 动一个 2⁻⁶ ⇒ 差值必须远超该界（本次 0 → 0.607）。
- 反例警告：朴素量化（`scale = max|row|/127`）的差值必须与"精确集"拉开量级，
  否则第 2 条测到的可能只是噪声 —— 本次 0.0098 vs 0。

### G9. int8 的体积比要按公式算，别拍"≥3×"
- **现象**：小模型上 int8 只有 f32 的 **2×**（不是 4×），一拍"≥3×"就假失败。
- **根因**：int8 的常量 = q（1 B/元素）+ 每**输出行**一个 f32 `scale`（4 B/行）：
  `比值 = 4 / (1 + 4/K)`。K=4 时是 2.0×，K=256 时才有 3.94×。
- **对策**：判据写成"实测 == 公式值"（容差 5%），并在报告里给出真实尺寸下的值；
  顺带也提醒：**per-row scale 不是免费的**。

### G10. 注意力的每头暂存槽可以共用，但**每头输出槽不能** ⭐⭐（V0.1.6）
- **背景**：注意力块的中间槽原来是按头命名的（`ATTN_q0/ATTN_q1/ATTN_kt0/…`）：
  H 个头 → 6H 个槽，`--slot-reuse` 也回收不到（它们在 `emit_attn` 内部生成，
  生命周期分析看不见）。V0.1.6 把它们分成两类处理。
- **可共用**（写完立刻读、读完不再有人读）：`q` / `k` / `kt` / `v` / `s` ——
  共 5 个角色，H 个头**轮流借同一批**（`ATTN_hq` / `_hk` / `_hkt` / `_hv` / `_hs`）。
  另外拼头目标 `<层>_ctx` 可以借 `_q`：最后一次读 `_q` 是**最后一个头**的 `GEMM s, qh, kt`，
  正好在拼头之前，且两者形状都是 `[T, D]`。
- **不能共用**：`c`（每头输出）。H 个头的结果要**一起活到拼头那一刻**，共用 ⇒ 拼出来的是
  同一份值拼 H 遍。**实测**：把 `c` 也改成共用（一行改动），四个注意力模型（T=1 / T=4 因果 /
  T=4 非因果 / 循环版）的 `--slot-reuse` 输出**全部**与不复用版不同（例：`-15.786533…` →
  `-1.170246…`）⇒ "输出逐字符相同"这条判据**可假**，不是恒真。
- **收益（实测，头=2、T=4、D=4）**：槽位 30 → 24，激活区 **1152 B → 768 B（−33.3%）**；
  注意力块的目的槽名 17 → 11，差额正好是 `5×(H−1)+1`。
- **对策/复现**：`tools/slot_reuse.ps1` 判据 3c 直接数槽名（而不是只比字节数），
  `tests/attention.rs::slot_reuse_shares_per_head_scratch_but_not_head_outputs` 是它的快速版。

### G11. 训练路径：`MSE_BWD` 的梯度在**第 3 个**操作数，而且官方运行时**不带** train feature ⭐⭐⭐（V0.1.6）
- **现象 1（静默错）**：照 `CE_BWD` 的样子写 `MSE_BWD dloss, y, tgt`，引擎 `exit=0`，
  打印出来的梯度**全是 0**。没有报错、没有崩溃。
- **根因**：两个损失反向的**操作数顺序不一样**，而且都写在 `core/src/interp.rs` 的注释里：
  * `CE_BWD`：`dst=logits, a=dy(写), b=target` —— 梯度在**第 2 个**；
  * `MSE_BWD`：`dst=y(预测), a=target, b=dy(写)` —— 梯度在**第 3 个**
    （对应 `train.rs::mse_bwd(y, t, dy, n)` 的形参顺序）。
  写错时 `dL` 被当成"预测"参与算 loss，真正的梯度写进了 `tgt`（一个常量槽）——
  于是"能跑、退出码 0、梯度全 0"。**这正是本项目最不能接受的一类失败。**
- **现象 2（跑不起来）**：就算指令写对了，官方 `vmlm-runtime.exe`（75,776 B 不变式那个）
  会 `exit=6` 并打印 `train feature disabled` —— 反向算子整体在 `#[cfg(feature = "train")]` 后面。
  同理，`ADAM/SGD/ADAMW` 在 `cpool_readonly` 下直接 `exit=9`
  （`weights are mmap RO; no training`）。
- **对策**：
  1. 前端把操作数顺序**写进生成物的注释**（`src/vmlgen.rs::emit_backward` 的头部表），
     并让 `ACT_BWD`/`GEMM_BWD_W` 的 dy 链在 `.vml` 里肉眼可查；
  2. 判据必须是**数值的**：`tools/train_ab.ps1` 用 numpy 中心差分当独立参考
     （实测最大相对误差 9.8e-06），并配 can-fail（扰动权重 ⇒ 梯度必变）；
  3. 运行时在 `out/` 下**隔离构建** `--features train`（`tools/train_ab.ps1` 判据 0/E），
     官方二进制的 SHA256 前后必须一致 —— 否则"为了训练把引擎改了"就没人发现。
  4. `构建时必须带 --target x86_64-pc-windows-msvc`：不带的话 `.cargo/config.toml` 里
     `/ENTRY`、`/NODEFAULTLIB` 那套链接参数不生效，报 `LNK2001: mainCRTStartup`（实测）。

### G12. `--slot-reuse` / `--loop-repeat` 与反向**只能二选一** ⭐⭐（V0.1.6）
- **现象**：三种能力看起来互不相干，实际放在一起会**静默算错**。
- **根因**：反向要读每一层的输入/输出激活（`GEMM_BWD_W` 的 `x`、`ACT_BWD` 的 `ypre`），
  而 `--slot-reuse` 会把"已经读完"的槽**回收给后面的层**、`--loop-repeat` 会让循环体
  每圈**覆盖**同一批槽 —— 反向读到的就是被改写过的值。
- **对策**：`反向` + 这两者一律硬失败 `E114` 并说清理由（不写"注意"、不给"警告后继续"）。
  这是**有意的能力边界**：先要正确，再谈激活区大小。

### C8. `x` 是 `重复` 的别名，`lin` / `act` 这类**层类型别名**当实例名会让 `连接`/`前向` 解析不到
- **现象**：写 `x = 线性 输入=4 输出=4`，下一行报
  `E005：重复 前面缺少被重复的层`（指向**下一行**，看起来完全不相干）；
  写 `lin = 线性 输出=2` + `连接 嵌入 lin`，报 `E005：连接至少需要 2 个层，实际是 空`。
- **根因**：`x`/`*` 是 `repeat` 的**精确别名**（`... x 24`），所以 `x = 线性 …` 里的 `x`
  被当成重复后缀；而 `连接`/`前向` 的解析要求"标识符"，层类型别名（`lin`/`act`/`norm`…）
  在那一层被当成关键字跳过，于是路径为空。
- **对策**：给层起名时**避开**关键字与层类型别名；`精确/前缀匹配`的规则见 `src/keywords.rs`。
  报错位置指向**下一行**是这两条的共同特征 —— 看到 E005 先检查上一行的名字。
  （`tests/train.rs` 的示例层名因此用 `l1`/`act`/`l2`/`h1`/`nm`，不是随便起的。）

### G13. `lower()` 只取常量名**最后一段** ⇒ 命名必须能把字段区分开（V0.1.6）
- **现象**：给注意力的 int8 反量化 scale 起名 `ATTN_Wq_scale`，生成出来的 Rust 编译报
  `E0124: field 'scale' is already declared` + `E0609: no field 'wq_scale'`。
- **根因**：`libgen::lower()` 是 `full.rsplit('_').next()` —— 它按"**<层前缀>_<字段>**"
  设计（`t__1_W` → `w`、`a__2_bWq` → `bwq`）。`ATTN_Wq_scale` 有两个后缀段，
  于是被压成 `scale`，与 softmax 的 `ATTN_scale` **撞成同一个字段**；
  而生成代码里引用的 `self.wq_scale` 根本不存在。
- **对策**：区分用的那段必须在**最后** ⇒ 改成 `ATTN_sWq`（→ 字段 `swq`）。
- **教训**：常量名不是随便起的 —— 它是**结构体字段名**的来源。加常量前先算一遍
  `lower()` 会把它压成什么；两个常量的"最后一段"相同就会撞。

## H. 仓库与版本化（V0.1.5）

### H1. `git init` / `git add -A` 必须**在目标目录里**跑 ⭐⭐
- **现象**：想给 `D:\czsai\sparrow` 建仓库，却因为工具默认 CWD 是 `D:\czsai`，
  实际执行成了对**父目录**初始化：`Initialized empty Git repository in D:/czsai/.git/`，
  紧接着的 `git add -A` 开始把整个 `D:\czsai`（含 `models.7z` 20 GB、`checkpoints.7z` 5 GB、
  各 `target\` 目录）往索引里塞 —— 命令直接跑过 120 秒没结束。
- **根因**：`git init` 作用于 CWD（或其 `--git-dir`），`git add -A` 同理；
  写脚本时「我以为我在哪个目录」和进程实际 CWD 是两回事。
- **对策**：
  1. 每个 git 命令都显式给位置：`git -C <dir> ...`，或调用工具时把 CWD 钉死成
     `D:\czsai\sparrow`（本次最终就是这么修的）。
  2. 事后**先看清路径再删**：`Get-Item D:\czsai\.git` 打印 `FullName` 与 `CreationTime`，
     断言 `FullName -eq 'D:\czsai\.git'` 才 `Remove-Item -Recurse -Force`。
  3. 目录里先放好 `.gitignore`（`/target/`、`/out/`）**再** `git add`，并检查
     `git status --porcelain` 的条数是不是预期的量级（296，而不是几十万）。
- **代价提示**：这种错误不报错、只是变慢，很容易被当成「磁盘慢」放过去；
  真让它跑完，`models.7z` 那 20 GB 会被压进 `.git`，删起来很痛。

### H2. 把「生成物」入库 ⇒ 换来一条强不变量
- **做法**：`examples/` 下的 `.spar/.vml/.vmb/.args/*_bins` 全是**生成物**，
  本仓库仍然把它们入库（`target/`、`out/` 除外）。
- **为什么值得**：于是「跑完全部验收驱动（清单见 `tools/verify_all.ps1` 的 `$drivers`）后 `git status` 必须为空」成为一条
  **可假**的不变量 —— 它同时验证了两件事：生成器是**确定性的**（同 seed 同字节），
  且验收过程**没有留下未回收的改动**。实测 PASS（`tools/verify_all.ps1` 判据 G0/G1）。
- **代价**：生成器一旦引入不确定（时间戳、哈希表迭代序、未固定 seed），这条判据就会红；
  那正是我们想要的信号 —— 但不能把「红了」当成噪声去关掉它。
- **注意**：`.gitignore` 必须先于 `git add` 存在，否则目标目录的 `target/`（本仓库 293 MB）
  会在第一次 `add` 时被暂存。

### H3. `.gitattributes` 写得对，但**旧文件在 index 里仍是 CRLF** ⭐
- **现象**：`git status` 干净、`git diff` 干净，看起来一切正常；但某天编辑 `src/main.rs` 保存后 `git add`，
  diff 是 **1,318 行**（整文件重写），`src/vmlgen.rs` 是 **3,922 行**。
- **根因**：`* text=auto eol=lf` **只影响"读入 index 时的归一化"，不会回溯改写已经入库的 blob**。
  实测本仓库有 6 个文件是 `.gitattributes` 生效**之前**入库的：`src/main.rs`、`src/vmlgen.rs`（整文件 CRLF），
  以及 4 个 `examples/attn_*.sparrow`（各 1 行 CRLF）。git 的 stat 缓存按 mtime+size 判"没变"，
  所以平时**完全没有症状**。
- **对策**：一次性归一化（把工作区这 6 个文件的 CRLF 换成 LF，或 `git add --renormalize .`），
  并用**两条独立判据**证明零内容改动：① 去掉 CR 后的 SHA-256 不变（6/6 SAME）；
  ② `git diff --cached --ignore-cr-at-eol` **输出为空**。
  验收：`git ls-files --eol | Select-String 'i/(mixed|crlf)'` 返回 0 条。
- **为什么值得单列**：它**没有症状**，只在"下一次编辑"时爆发，且爆发时看起来像"我手滑改了整文件"。
  同一个坑在 `D:\czsai\vmlmd` 咬过一次（那边 `.gitattributes` 的注释就是为此写的）。

## I. 槽位复用（V0.1.3 输出槽 / V0.1.5 暂存槽）

### I1. 暂存池的桶键必须含**行数**（形状要精确匹配）⭐
- **背景**：V0.1.5 把"活到本层读完就死"的中间槽也回收了：汇入的 `<层名>_in`、
  循环组的进位槽 `__in` / 汇入槽 `__m` / 计数器 `__ctr` / 两个步长槽 `__ls`/`__ns`。
- **坑**：既有的输出槽池按**输出宽度（列数）**分桶就够用（同一个模型里 T 相同），
  照抄到暂存池就会出错：循环进位槽是 `(1, D)`，而 T>1 时层输出槽是 `(T, D)` ——
  两者列宽相同、**行数不同**，汇编器为它们分配的激活区字节数也不同（按最终形状 64 B 对齐紧密排布）。
  一旦互借，`SHAPE` 会被以不同形状重声明，"复用只改写哪个槽、不改数值"就不再有保证。
- **对策**：暂存池键用 `(行, 列)`；借出与归还都按精确形状匹配（保守但可证）。

### I2. 中间槽的名字形状与输出槽不同 ⇒ 不能并进同一个池
- **现象**：输出槽的池存"基名"，真正槽名是 `<基名>_out`（`emit_layer_body` 自己拼后缀）；
  而中间槽叫 `<层名>_in` / `<last>__m` / `<last>__ctr`，**不符合**那个约定。
- **对策**：另开一个池，里面存**完整槽名**；并且让汇入的 dst 变成参数
  （`emit_merge` → `emit_merge_into(dst)`），这样 dst 才能来自池。
- 附带效果（实测）：12 层残差的激活区从 1664 B 降到 **256 B**（V0.1.3 只到 960 B），
  循环组也能省了；结构判据直接数汇入中间槽的名字个数：**12 → 1**。
