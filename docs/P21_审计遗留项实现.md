## 第二组：head 反向按 token 批量 GEMM 化（已实现，保留**分块版**）

**做法**：新增 `core/src/kernels.rs::head_bwd_batched_avx2` —— 把「对 token 的求和」放进寄存器：

```
dW[v][j]  = Σ_t dY[v][t] · Ht[(v%nb)*k0e + j][t]      （dY = dlogitsᵀ，Ht = head 输入ᵀ）
dHt[s][t] = Σ_{v: v%nb==b} dY[v][t] · w[v][j]          （s = b*k0e+j，t 维向量化、连续 RMW）
```

配套复用已有的 `transpose_t8_avx2` / `transpose_t8_back_avx2`；trainer 侧新增 `head_bwd_batched`
（thread-local scratch，head 与 head2 两个调用点都接上，`nt_in<=1` 时生效）。

**① 逐值对拍**（`kbench --mode hbatch`，nv=8198 / dim=2048 / nb=128 / k0e=k0h=16 / tt=128）

| 量 | 逐 token 参考 | 批量 | maxdiff | 比值 |
|---|---|---|---|---|
| `dw` | 4.655018e0 | 4.655019e0 | 1.67e-6 | **1.00000** |
| `dh` | 2.738916e0 | 2.738916e0 | **0.0（逐位相同）** | 1.00000 |

**② 内核计时**（同上形状，含 3 次转置）：逐 token **3.884** ms/round → 批量 **2.537** ms/round = **1.53x**。

**③ 接进 trainer（primary 100 步，同会话顺序，基线 = 第一组收盘）**

| 版本 | median | min | 相位 head 反向 | 相位 嵌入反向 | 结论 |
|---|---|---|---|---|---|
| 第一组收盘（逐 token） | 0.1491 | 0.1446 | 8.264 s | 7.393 s | 基线 |
| 批量·**整块转置**（tt=128 一次转置） | 0.1572 | 0.1537 | **10.913 s**（更差） | 8.281 s（更差） | **否决**：4.2 MB dlogits 转置进出 DRAM，加进去的流量 > 省下的 RMW（省下的 0.5 MB dw 本来就在 L2） |
| 批量·**分块 C=32**（dY 1 MB / Ht 262 KB，留 L2） | **0.1451** | **0.1423** | **6.300 s（−24%）** | **4.320 s（−42%）** | **保留**：端到端 −2.7%，两个 head 反向相位合计 −5.0 s |

* 分块版的动机直接来自 t8 与整块版的实测教训：**加进 DRAM 的流量会在 trainer 里被放大**，
  所以把「一次转置 4 MB」改成「每 32 token 转置 1 MB」——同一份数据搬运，落在 L2 而不是 DRAM。
* 红线：`--gradcheck 1` **PASS 40/0**；loss 曲线与第一组**逐位相同**（9.01232 → 9.00347）；
  `vmlm-tests` 全部 PASS；无 NaN/崩溃。快照 `_opt/p21_g2_src/`。

## 第三组：attention 反向 passB/passC GEMM 化（已实现 → **实测更慢 → 回退接线**）

**做法**：新增 `core/src/kernels.rs::attn_bwd_bc_blocked_avx2` —— 把 4 行累加器放进 ymm
寄存器、按 d 的 8 宽分块扫，每块只读一次 `dobuf[i]/q[i]/k[j]`：
`dv[j] = Σ_{i≥j} P[i][j]·dobuf[i]`、`dk[j] = Σ_{i≥j} D[i][j]·q[i]`、`dq[i] = Σ_{j≤i} D[i][j]·k[j]`。
trainer 侧接进 `attn_core_bwd` 的 AVX2 路径（`--attn-window 1` 生产路径不走 `_par` 的并行分支）。

| 步骤 | 结果 |
|---|---|
| 第一版（漏了 `zero(dk); zero(dq)`） | `--gradcheck 1` **32/40 越界**，worst rel 5.1e10 ⇒ 立刻抓到（提示：dv 在函数开头清零，dk/dq 原本在被我替换掉的那段里清零） |
| 修掉清零后 | gradcheck **4/40 越界**（勉强），worst rel 3.547 ≈ 与通过基线 3.568 同档（受噪声限制的探针在容差边缘） |
| 100 步实测 | median **0.1493** / min 0.1445 · wall 16.40 s —— 对比第二组收盘 0.1451/0.1423 ⇒ **+2.9% 更慢** |
| 处置 | **回退接线**（内核保留在 core，结论留档）。回退后复测：gradcheck **PASS 40/0**、median **0.1448** / min 0.1423、loss 与第二组逐位相同 ✓ |

**为什么「流量降到 1/4」反而更慢**：分块把 `_mm256_set1_ps(p)` / `set1(ds)` 的**广播次数**
从「每对 (i,j) 一次」放大到「每 (i,j,d-chunk) 一次」——即 ×（d/8 = 256）。原路径的 2 次广播
摊在 4096 个 MAC 上，分块版是 8 次广播摊在 64 个 MAC 上 ⇒ 端口 5 被打满，收益被吃光。
要真正兑现「按行复用」，必须让 **j 维度进 lane**（P/ds 变成一次 4 元素 load，而不是广播），
那要求 P/ds 以转置布局存放 —— 属于第四组「布局改造」的同一类工作。

## 第四组：整栈 source-major 布局改造（P20 §3.2）—— 待做（**执行规格已就绪**）

前三组已把这个改造的两个边界条件实测出来：① 单点收益真实（kbench t8 前向 1.83x / 反向 2.20x，含转置）；
② **每层转置=亏**（drop-in 端到端 0.86x/0.75x）；③ **转置必须落在 L2**（head 反向整块 4.2 MB 转置 −5.4%，
分块 32 token 后 +2.7%）。

### 执行规格（train/src/b1_full_train.rs::step_fn）

| 步骤 | 改动 |
|---|---|
| S1 | `h_ins[l]` 的解释从 `[tt][dim]` 改成 `[dim][tt8]`（**同一块内存，不额外分配**；`t8=ceil(tt/8)*8`）；新增 `dy_t8/dx_t8`（各 `dim*t8`） |
| S2 前向 | 嵌入输出 `h0` 保持 token-major（散写不变）→ **一次转置** `h0→h_ins[0]`；随后**连续非注意力层直接 `b1_forward_t8(&scs[l], h_ins[l], t8, tt, h_ins[l+1])`，零转置** |
| S3 注意力边界 | 到 `(l+1)%attn_every==0`：`h_ins[l+1]→dest`（token-major，一次转置）→ 现有 attention 代码 → `dest→h_ins[l+1]`（写回 t8）；末层输出转置进 `h` 供 head 用 |
| S4 反向 | head 反向产出的 token-major `dh` → 一次转置进 `dy_t8`；层反向用 `kernels::b1_backward_t8_avx2`（**已实现且对拍通过**：dw/dx 比值均 1.00000），`dx_t8` 直接是上一层的 `dy_t8`（**零转置**）；注意力边界 `dy_t8→dh` → 现有 attention 反向 → 其 `adx` 转置回 t8 |
| S5 底部 | 末层 `dx_t8→dh`（一次转置），嵌入反向 / `etab_g` 散加不变 |
| S6 计数 | 每步转置 ≈ 1+2·n_attn+1 +1+2·n_attn+1 = **16**（primary n_attn=3），drop-in 是 54 |
| S7 验证 | 每步都：`--gradcheck 1` PASS → 100 步 median/min → loss 与第二组逐位对比；不达标即回退 `_opt/p21_g3_src/` |

**风险**：`h_ins` 只改解释不改分配 ⇒ 出错表现为数值错而非崩溃（gradcheck 会抓）；
转置必须在**整块 tt** 上做，attention 新旧代码仍只在 token-major 视图上工作。
**外推**：转置流量降到 1/3–1/4 后前向/反向各 1.6–2.0x，端到端 ≈ −30%（逐层反向占 53%）。

## P22：第三组「正解（j 维进 lane）」与 KV 流量削减 —— 三实现全部实测更慢（结论有机制）

### 试过的三种实现（都通过 gradcheck，都被实测否决）

| # | 形态 | 端到端 | 根因（实测） |
|---|---|---|---|
| 1 | passB/passC 寄存器分块（4 行累加器 + d 的 8 宽扫） | **+2.9%**（0.1451→0.1493） | `set1(p)/set1(ds)` 从「每对 (i,j) 一次」放大到「每 (i,j,d-chunk) 一次」= ×256 |
| 2 | 4 行共享一条 K/V 行的点积内核 `dot4_shared_avx2`（前向核心 + 反向 passA 改 j 外层） | **+8%**（0.1446→0.1564） | 共享 V 行使系数必须回到 x 循环内广播：每 8 个 MAC 一次 vs 原来每 4096 个 MAC 一次 |
| 3 | head 反向整块转置（同族，P21 第二组） | +5.4% | 4 MB 转置进出 DRAM；分块 32 token 后转正（−2.7%，已保留） |

**机制一句话**：现有 `axpy/axpy2/dot256` 把「标量系数广播一次、摊到整条 d=2048 的行上」，
即 2 次广播 / 4096 MAC；任何「按行复用」的分块都会把广播拉进向量循环 ⇒ 广播次数 ×100–500 ⇒ 端口 5 打满。
在 t=64、d=2048 下 Q/K/V 行共 512 KB×3，**L2 常驻**，所以「减流量」本来就没有 DRAM 收益。

### 算法级（约分/消元）结论

* **成立且已代数验证的恒等式**：`rowsum[i] ≡ Σ_j P[i][j]·dprob[i][j] = dobuf[i]·o[i]`
  （`o[i] = Σ_j P[i][j]·v[j]` 就是前向已缓存的 `ao[b]`）⇒ 行均值可用 t 次点积得到，不必搭 passA 的 t² 次；
  以及 `Σ_j ds[i][j] = 0`（因 `Σ_j P[i][j] = 1`），可作免费的自检、并允许把 `k[j]` 平移任意行内常数而不改 `dq[i]`。
* **不可约的主项**：`ds` 依赖每一对的点积 `dobuf[i]·v[j]`，因此 `dv/dk/dq` 的任何展开都仍需 t²·d 的成对乘积。
  softmax attention 反向的 Ω(t²d) 是算法固有的 —— 唯一的算法级削减是把 t² 降下来（`--attn-window` 已在用），
  以及低秩/线性近似（会改数学，未做，需要 loss 对照才能落地）。

| P22 两处接线 | **已回退**（`_opt/b1_full_train.pre_p22.rs`），保留 `core::kernels::dot4_shared_avx2` 作留档 |

## P23：端口压力实测 + 三个 A/B

### A/B 1 地址计算（端口 5 → 端口 6）：**没有可搬的东西**
* 静态census（`core` 汇编，8 个热点内核，函数体内指令）：**`lea` 计数全部为 0** —— 地址运算已被折叠进 AGU 寻址模式（`[base+index*4]`），或由 `add` 承担。
* 源级 A/B（kbench `--mode addr`，生产形状 per_token=32768、t=256，同一数学两种取址形态）：
  | 形态 | ns/conn |
  |---|---|
  | (a) 指针步进 | 2.1260 |
  | (b) 每次重算 `row*per + x` | 2.1202 |
  | 比值 (b)/(a) | **0.997x** |
  ⇒ 下标重算已经免费（LLVM 强度削减/寻址模式吸收），**Rust 里也无法手写 `lea`**。真正的端口 5 压力来自广播/洗牌：census 里 `axpy2_256_f32` 2 条、`b1_forward_packed_avx2` 12 条、`b1_forward_t8x4_avx2` 4 条 p5 类指令；这些在现有内核里已是「每次调用一次」的最优摊法（P22 三个阻塞实验正是破坏了它才变慢）。

### A/B 2 bf16 内联扩展 vs f32：**1.21x 慢**
kbench `--mode bf16`，生产形状（每 token 32768 个权重）：
| 变体 | ns/conn | 相对 f32 |
|---|---|---|
| (a) f32 权重 | 1.2064 | 1.00x |
| (b) bf16 存储 + 内层内联扩展（`vpmovzxwd`+`vpslld`） | 1.4561 | **1.21x** |
| (c) bf16 存储 + 预扩成 f32 | 1.2090 | **1.00x** |

### A/B 3 预扩展（移出内层）：内层**零**开销，端到端 +0.5%
* 内核级：(c) = 1.00x（与 f32 无异），(b)−(c) = +2.07 ms/round ⇒ 内联扩展的全部代价就是每 8 权重多 2 条微指令（其中 1 条占端口 5）。
* 端到端（生产配置 dim4096/L32/batch32，100 步，`--w-bf16 0/1`）：
  | 变体 | s/step | 首步 loss | 末步 loss |
  |---|---|---|---|
  | f32 权重 | **1.1988** | 9.012793 | **8.963350** |
  | bf16 权重（每步就地圆整） | 1.2048（+0.5%，即每步一次 O(#权重) 圆整） | 9.012793 | **9.009610** |

### 验收对照
* 不崩溃 ✓（两种都跑满 100 步）；不 NaN ✓（loss 全有限）。
* **loss 一致 ✗**：bf16 **参数存储**损失严重——100 步只降 0.0031，而 f32 降 0.0490（≈16 倍学习量差距）。
  机制：本实现每步就地圆整**主权重**（8 位尾数 ⇒ 相对精度 2^-9≈2e-3），把优化器累积的低位全部抹掉；
  标准混合精度做法是**保留 f32 主副本 + Adam 状态**，另建一份 bf16（或预扩 f32）缓冲只给计算内核用。
  那种形态下 loss 应与 f32 基本一致（只有前反向算术精度差异），而速度代价就是 A/B 3 量到的 +0.5%（纯内存换）。
  **该镜像形态本轮未实现**，因此 "loss 一致" 这条目前**只在"bf16 作参数存储"的意义下被证伪**。
* `--w-bf16` 默认 0 ⇒ 生产路径不变（gradcheck PASS 40/0、`vmlm-tests` 全部 PASS 已复验）。

### P23b：--w-bf16 改成**镜像形态**（f32 master + bf16 精度 compute 缓冲）

设计落地：Adam 只更新 `sp_master[l] / head_master / head2_master`（f32），每步在 WT 重打包之前把
master → compute 缓冲（`bf16_to_f32(f32_to_bf16(x))`，O(#权重)、内层零开销）；前向/反向读 compute 缓冲。
镜像张量 = 32 层 + head + head2（嵌入表与 attention 投影仍 f32）。

| 判据 | 结果 |
|---|---|
| gradcheck（镜像开） | **PASS 40/0** |
| 生产 100 步 loss（dim4096/L32/batch32） | f32 `9.012793 → 8.963350`；镜像 `9.012793 → 8.963364` ⇒ **Δ=1.4e-5（相对 1.6e-6，ε 级）** |
| s/step | f32 **1.1996** → 镜像 **1.2120** = **+1.03%** |
| 对照：上一版「就地圆整主权重」 | loss 只降到 9.009610（学习量崩）⇒ 镜像形态修好了这个问题 |

**两种镜像实现（数值完全相同，只有载体不同）**
| 形态 | 内存 | 速度 | 状态 |
|---|---|---|---|
| (a) master f32 + compute **f32**（本次实现，预扩展） | 镜像张量 **×2**（不减反增） | **+1.03%**（实测） | 已实现 |
| (b) master f32 + compute **bf16(u16)** + 内核内联扩展 | 镜像张量 ×1.5（相对 f32 省 25%） | 权重读路径 **1.21x**（A/B 2 实测，端到端未测；真核心里 gather 占大头，惩罚会被稀释） | 未实现 |

⇒ 结论：**「省一半内存」与「速度基本不变」不能同时成立**。bf16 镜像的价值是「让 bf16 参与计算而不丢学习量」，
不是加速；要省内存必须付内联扩展的端口 5 代价（A/B 2 已量化）。
