# 在国内网络下访问本仓库（实测）

> 起因：仓库公开后，维护者与部分用户**打不开 `github.com`**（SNI 阻断）。
> 下面每一条都是**在墙内实测**的结果（2026-10-15，Windows + PowerShell 7），不是猜的；
> 数字会随线路变化，但"通/不通"的分类在本机是可复现的。

## 1. 结论速查

| 用途 | 入口 | 实测 |
| --- | --- | --- |
| 元数据 / 单文件（程序化） | `https://api.github.com/repos/shouzugzs-AI/Sparrow` | ✅ **HTTP 200**，0.7 s |
| 浏览网页 / 读单文件 | `https://gh-proxy.com/https://github.com/…`、`…/https://raw.githubusercontent.com/…` | ✅ **HTTP 200**，~2 s |
| 下载整包 zip | `https://gh-proxy.com/https://github.com/shouzugzs-AI/Sparrow/archive/refs/heads/main.zip` | ✅ **HTTP 200**，3.3 MB / 8.2 s |
| git 推送/拉取 | **SSH over 443**（`ssh.github.com:443`，见 §3） | ✅ 推送成功 |
| 整包（备用） | `https://codeload.github.com/…/tar.gz/refs/heads/main` | ⚠️ HTTP 200，但 2.7 MB 用了 **205 s**（~13 KB/s） |
| — | `github.com` 网页、`raw.githubusercontent.com`、`cdn.jsdelivr.net`、`ghproxy.net`、`ghfast.top` | ❌ 超时 / SSL 重置 |
| 镜像平台 | `gitee.com`、`gitcode.com` | ✅ 均可访问（HTTP 200），适合做镜像（§4） |

## 2. 三条常用命令

```powershell
# ① 只读一个文件（api.github.com，返回 base64）—— 最稳，不依赖任何第三方
$j = (Invoke-WebRequest 'https://api.github.com/repos/shouzugzs-AI/Sparrow/contents/sparrow/Cargo.toml' `
      -Headers @{'User-Agent'='x'} -UseBasicParsing).Content | ConvertFrom-Json
[Text.Encoding]::UTF8.GetString([Convert]::FromBase64String($j.content))

# ② 读原文（走第三方代理，快）
(Invoke-WebRequest 'https://gh-proxy.com/https://raw.githubusercontent.com/shouzugzs-AI/Sparrow/main/README.md' `
 -UseBasicParsing).Content -split "`n" | Select-Object -First 5

# ③ 下载整包
Invoke-WebRequest 'https://gh-proxy.com/https://github.com/shouzugzs-AI/Sparrow/archive/refs/heads/main.zip' `
 -OutFile Sparrow-main.zip
```

## 3. git：走 SSH 的 443 端口（推荐）

`github.com:22` 与网页 443 都不通，但 **`ssh.github.com:443`** 通。在 `~/.ssh/config` 里写：

```
Host github.com
  HostName ssh.github.com
  Port 443
  User git
```

验证与克隆：

```powershell
ssh -T git@github.com          # 应回：Hi <user>! You've successfully authenticated...
git clone git@github.com:shouzugzs-AI/Sparrow.git
```

## 4. 给国内受众：镜像（Gitee / GitCode）

`gitee.com` 与 `gitcode.com` 实测可访问。两种做法：

* **平台导入**（推荐，能自动定时同步）：Gitee「新建仓库 → 从 GitHub 导入」；
  GitCode 有同类功能。导入后在「仓库镜像管理」里开定时同步。
* **手工推送**（一次性或定期）：

```powershell
git remote add mirror <镜像仓库的 SSH 地址>
git push mirror main --tags
# 核验：两边 HEAD 必须相同（镜像有没有跟上，用这个判，不看网页）
git rev-parse main
git ls-remote mirror refs/heads/main
```

镜像建好后，建议在 README 顶部给出镜像链接，并注明：
**镜像只做分发便利，许可与声明以本仓库的 `LICENSE` / `LICENSE-NOTICE` 为准**；
issue / PR / Actions 仍在 GitHub。

## 5. 注意事项（不藏）

1. `gh-proxy.com` 这类**第三方代理**会看到你请求的 URL 与返回内容（本仓库是公开内容，
   没有敏感信息），但它的可用性不由我们控制，随时可能失效；**不要**用它传凭据。
2. `codeload.github.com` 可达但极慢（实测 ~13 KB/s），只适合小仓库应急。
3. 常见的 `cdn.jsdelivr.net/gh/...` 方案**在本机不通**（SSL 重置），别照抄网上的教程。
4. 镜像仓库是**副本**：许可证以本仓库为准；`git push mirror` 只推 `main` 与标签，
   分支/issue/Actions 不会同步。
5. 上表是**一次实测**，不代表你所在线路。判断方法就在本文件：把命令抄下来跑一遍，
   超时 12 s 记"不通"。
