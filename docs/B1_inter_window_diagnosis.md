# 排查报告：inter + window 下 attention 体检「假坍缩」与静默退出

## 结论速览

| 你的问题 | 答案 |
|---|---|
| **1. 体检在哪个 view 上做？** | **在"整块 t_tokens"的 view 上**（`let tt = t_tokens;` 把区域 tt 遮蔽了）。逐窗口模式下 `aq/ak/aprob` 只是**共享工作缓冲**，循环结束后只剩**最后一个窗口**（64 token）的内容 ⇒ 按 2048 读 ⇒ 99.9% 是 0 ⇒ **非零占比=0.0010 = 64²/2048²**、集中度≈0 ⇒ **这是假坍缩，不是 attention 坏了**。**已修**。 |
| **2. 标定的 g 是否乘进了每个 slot 的 Wq/Wk？** | Wq/Wk 是**共享**的（inter 没有每 slot 权重副本），g 只乘一次 ✓ 没问题。**但标定的"测量"是 window-blind 的**：它读的是（被覆盖成最后一个窗口的）共享缓冲，却又按整块统计 ⇒ **量错了**。另外它依赖 body 内 `collect_flag` 的**副作用**，而该副作用会被更早的一次前向消费掉 ⇒ inter+window 下标定量到 **0**。**已改成直接、window-aware 地量 `aq/ak`**。 |
| **3. 集中度判据失败有 exit + 消息吗？** | **原来没有**：代码只把集中度**打印**出来，唯一的 FATAL 判据是 `max|q·k| <= 0.01`。**已新增**集中度/非零占比判据：`<0.5` ⇒ 打印原因 + `exit 2`；`<=1.0` ⇒ 警告（因为初始化后本就接近均匀，实测 1.00~1.08）。 |
| **4. 内存分配失败被吞掉了吗？** | 没有：`alloc()` 是 `malloc` + `assert!(!p.is_null(), "OOM …")`，panic=abort 会**打印**。**但我的 inter 版本按 `nslot * t_tokens²` 分配 `aprob/adprob`** ⇒ batch32/4线程下 **2×2.1 GB**（实际只需 ~33 MB/slot）⇒ 极易 OOM/触发 assert。**已改成 slot0 用 t_tokens 尺寸、其余 slot 用 region 尺寸** ⇒ 降到 ~160 MB。 |

## 本轮已修（可验证）

1. **体检 view**：逐窗口 → 按 `t = seq` 读，并打印 view 与窗口数（B 分支的数字从假坍缩恢复为 集中度 1.064/非零 1.0000）。

## 关于「静默退出」

* 我**审计了全部 25 处 `process::exit`**：每一处前面都有 `println!`/`eprintln!` ⇒ **当前代码没有静默退出路径**（列表见下）。
* 你看到的静默退出，最可能是**上一版（per-slot 步长写错/共享 scratch 未私有）的二进制**在 SEGFAULT（退出码 `0xC0000005`，无任何输出），
  或者进程被外部结束。**现在 D 组合会明确报错**。
* 若你仍看到静默退出，请给我 **`%ERRORLEVEL%`**（或 `echo %ERRORLEVEL%`）：`0xC0000005` = 访问越界；`0xC0000409` = abort；`2` = 判据失败。
  （exit 点：262/267/271/961/972/981/1347/1353/1414/1418/1533/1590/1605/1671/1679/2258/2817/2824/2840/2866/2925/2960/3278/3412/3851 —— 均有消息）
