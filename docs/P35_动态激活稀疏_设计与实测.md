# P35 动态激活稀疏（稠密权重 + 每 token 掩码）设计与实测

> 目标：不删权重、不改稀疏存储格式。权重全稠密，**稀疏性来自每 token 动态选择的一小撮激活通道**；
> 一个掩码在层内复用给注意力、隐藏层、FFN；掩码由注意力层自身的激活强度决定（可学）。
> 首轮口径：先证**质量**（等 FLOP 下 loss 更低），胜出后再做效率（Rust 布局 + 墙钟）。

## 0. 结论先行

> **本篇 §6.2 / §6.5 的读法已被后续实测修正，请对照 `P35b_学习率与长程_实测.md`。**
>
> §6.2 里"keep=5% 转负、只有 15% 在同 FLOP 下略胜"是在**双方都用 lr=3e-4** 下得到的；
> 后续把学习率按稀疏率调开（C15→2e-3、C5→5e-3、C1→5e-3）后，4000 步、16.4M token 的结果是：
> C15（3.264M MAC）4.33 对稠密 d=112（3.499M MAC）4.63，**领先 0.285**；C5 与 d=80 打平。
> 也就是说"稀疏优势随训练变长而消失"不成立，真正的原因是**小 keep 的臂被欠训**。
> §6.2 的**结构指标**（选择熵、并集、n_pat、跨域重叠、死通道定义）仍然有效，只是结论要重读。

- 设计层面的四条断言（掩码由 |h| 选、层内复用、省计算、需要直接索引）都成立；
- 第一轮（keep=56.25%，2M token）：同 FLOP 下 −0.151 nats，train loss 同步更低（非正则化假象）；
- 极端稀疏（1%）是确定的负结果：244 步 +0.668、4000 步落后稠密 d=64 0.665；
- 5% 是当前性价比拐点，15% 是绝对质量拐点（详见 P35b）。

## 1. 方案拆成 5 条断言

| # | 断言 | 判定 |
|---|---|---|
| 1 | 掩码由**注意力层激活强度**选 | 可行。从零建模型令 `heads × head_dim = d`（方阵 q_proj），Q 通道号 ≡ 残差通道号 ≡ FFN 输入通道号，无需 2048→1536 映射 |
| 2 | 一个掩码**复用**给同层注意力 + 隐藏 + FFN | 严格成立的唯一形式：掩码在**残差通道空间**；本层 attention 算出的掩码给本层 FFN，并作为**下一层 qkv 的输入掩码**（一拍流水） |
| 3 | 因此省计算 | 一个 h 掩码覆盖 71.3% FLOP，加 FFN 中间掩码覆盖 92.2%（见第 3 节） |
| 4 | 而且是"直接索引" | 数学成立（只乘选中列）；但**每 token 切权重**的访存代价是 O(m·out)/token，远大于省下的 FLOP。可行落地形态见第 4 节 |
| 5 | 掩码计算本身可学 | 两种：Wq 硬 top-k（选择梯度为零，选择只由 attention 驱动）/ STE 软代理（选择梯度回流 Wq） |

## 2. 架构 spec（第一版）

```
每层 l（l = 0..L-1）：
  x       残差流 (B,T,d)
  h1      = RMSNorm(x) ⊙ M_{l-1}
  q,k,v   = W_q h1, W_k h1, W_v h1            # K 维被裁：只读 m 个 h 通道
  attn    = softmax(q kᵀ/√hd) v
  xa      = x + W_o attn
  M_l     = top-m( |Q| per channel )          # 注意力层算掩码（方阵 Q，通道对齐）
  h2      = RMSNorm(xa) ⊙ M_l
  act     = silu(W_gate h2) * W_up h2
  act     = act ⊙ Mid_l,  Mid_l = top-m( |act| )   # FFN 中间空间，独立掩码
  x       = xa + W_down act                   # K 维被裁：只算 m 个 FFN 神经元
输出：
  x_final = RMSNorm(x) ⊙ M_{L-1}
  logits  = x_final @ Eᵀ                      # K 维被裁，覆盖 13.9% FLOP
```

- `M_{-1}` = 全 1（第 0 层不裁）。
- 只做**输入侧**（K 维）截断：o_proj 与 attention core 不动（用户口径）。
- 掩码数：每层 2 个（h 空间 1 个 + FFN 中间空间 1 个），**不是**每层 6 个。

## 3. FLOP 账（d=256, L=12, I=1024, V=8198, seq=128）

总 MAC/token = **15.075M**。

| 可裁部分 | 掩码 | MAC/tok | 占比 |
|---|---|---|---|
| qkv 的 K 维 | h 掩码 | 2.36M | 15.7% |
| gate/up 的 K 维 | h 掩码 | 6.29M | 41.7% |
| lm_head 的 K 维 | h 掩码（末层） | 2.10M | 13.9% |
| down 的 K 维 | FFN 中间掩码 | 3.15M | 20.9% |
| o_proj + attention core | — | 1.18M | 7.8% |

| keep | MAC/tok | 相对稠密 |
|---|---|---|
| 0.75 | 11.601M | 1.30× |
| **0.5625** | **8.996M** | **1.68×** |
| 0.50 | 8.127M | 1.85× |
| 0.25 | 4.653M | 3.24× |

等 FLOP 对照：稠密 d=192 L=12 = 8.947M（与 keep=0.5625 差 0.5%）。

## 4. "直接索引"的真实代价

掩码稠密 GEMM（`x ⊙ M` 后满乘）与真稀疏计算**数学完全等价**，所以质量实验不需要任何布局技巧，
FLOP 按解析值记账，**脚本不报墙钟加速**。真正落地时：

- **每 token 切权重不可行**：keep=0.5625 时 gate/up 每 token 每层要复制 `144×1024×2` 个权重 ≈ 1.2 MB，
  而省下的算力按 30 GMAC/s 只值 0.4 ms——访存远贵于计算。
- **可行形态**：通道按全局激活频率排序（热通道靠前）→ 一批 token 取**并集掩码**，每步切一次权重、
  整批共用一个瘦 GEMM，算力按并集大小折算。并集多小取决于掩码相关性，是**实测指标**（P35 的 `union` 统计）。
- 若并集 ≈ 1.0（每 token 掩码互不相同），则只能在 token 粒度做瘦 GEMM（访存受限），
  或退化为"每 N token 共享一组掩码"（用户已否，理由是共享会串、丧失 specialization）。

## 5. 实验协议（与 P32 完全同一数据/游标/验证集/优化器）

- 数据 `artifacts\zh_wiki`，char vocab 8198，train 37.47M ids，val 78.4k ids
- batch 32 × seq 128 = 4096 tok/step，游标 `(seed*977) % (N-seq-1)`，每步 `+= 4096`
- val：4 个固定 batch，`base=(eb*977 + b*seq*13)%(N-seq-1)`，`(seq-1)*batch` 上平均 CE
- Adam(0.9,0.999)，per-tensor clip 1.0，warmup 30 + cosine 到 3e-5
- 首轮：488 步 = 2.0M tokens/臂，5 臂：dense256 / dense192(等 FLOP) / h / q / q-ste

## 6. 实测结果

### 6.1 第一轮（keep=0.5625，2M tokens，seed 1）

| 臂 | 掩码 | train | val@2M | MAC/tok | 相对等 FLOP 的 Δ |
|---|---|---|---|---|---|
| A | 无（d=256） | 5.9116 | 6.0282 | 15.075M | — |
| B | 无（d=192，等 FLOP） | 6.0198 | 6.1217 | 8.947M | 基准 |
| C | \|h\| top-56.25% | 5.8389 | **5.9710** | 8.996M | **−0.151** |
| D | \|Q\| top-56.25%（流水一拍） | 6.0514 | 6.1666 | 8.996M | +0.045 |
| E | \|Q\| + STE | 6.0462 | 6.1564 | 8.996M | +0.035 |

- \|h\| 掩码在同 FLOP 下好 0.151 nats，且 train loss 也低 0.073 ⇒ 不是正则化假象。
- \|Q\| 掩码比等 FLOP 的稠密还差 ⇒ **Q 通道只是索引对齐，不是信息对齐**；|h| 才是被裁 GEMM 的真实输入。STE 只回收 0.010。
- 并集（4096 token）：keep=50% 时 = 1.000，即 50% 稀疏无法批量化。

### 6.2 第二轮（keep=1~15%，1M tokens，244 步，同协议同 schedule）：质量 + 分化指标

等 FLOP 对照（组内同 schedule，可直接比）：

| 臂 | 有效 MAC/tok | val | 同 FLOP 稠密臂 | 稠密 MAC | 稠密 val | Δ(稀疏−稠密) |
|---|---|---|---|---|---|---|
| h keep=15% | 3.264M | **6.6833** | d=112 | 3.499M | 6.7194 | **−0.036**（稠密还多 7% FLOP） |
| h keep=5% | 1.874M | 6.9033 | d=80 | 2.008M | 6.8199 | +0.083 |
| h keep=1% | 1.319M | 7.6278 | d=64 | 1.409M | 6.9599 | **+0.668** |
| h keep=5%，不裁 FFN 中间 | 4.863M | 6.9038 | — | — | — | 与 h05 同 loss 但多 2.6× FLOP |
| 稠密参考 | | | d=92 | 2.521M | 6.7603 | |

分化指标（取最后一次 eval；随机基线 = 同 keep 同形状随机掩码）：

| 臂 | H_mask | H_mid | 数值熵 h/mid | 有效维 h/mid | 保留 h/mid | n_pat /4096 | pat_H | top_share | jac_w/jac_c | 随机 jac比 | 并集 | 死神经元率 |
|---|---|---|---|---|---|---|---|---|---|---|---|---|
| keep=15% | 0.780 | 0.861 | 0.852/0.888 | 112/470 | 38/154 | 1651 | 0.594 | 0.330 | 0.745/0.724=**1.05** | **1.05** | 0.804 | 0.000 |
| keep=5% | 0.642 | 0.744 | 0.813/0.896 | 90/498 | 13/51 | 351 | 0.207 | 0.730 | 0.849/0.850=**1.03** | 1.46 | 0.470 | 0.000 |
| keep=1% | 0.468 | 0.570 | 0.839/0.900 | 84/499 | 3/10 | **126** | 0.148 | **0.854** | 0.741/0.693=1.07 | (5.0 噪声) | 0.265 | 0.000 |
| keep=5% (mid 不裁) | 0.646 | 1.000 | 0.795/0.901 | 88/505 | 13/1024 | 486 | 0.216 | 0.722 | 0.833/0.812=1.03 | 1.46 | 0.539 | 0.000 |
| 初始化 | 0.986 | 0.997 | 0.949/0.918 | 193/542 | — | 3338 | 0.954 | 0.006 | 0.358/0.031=11.5 | — | 1.000 | 0.000 |

判读：
- **jac_w/jac_c ≈ 1.0**（keep=15% 与随机基线 1.05 完全一致）⇒ 掩码**没有**"同领域倾向同一组合"的结构；
  初始化的 11.5× 重合是相邻字的数据相似性，训练后消失。
- **top_share / n_pat** 随稀疏率恶化：keep=5% 时 73% 的 token 用同一个 13 通道掩码（351/4096 种）；
  keep=1% 时 85% 的 token 用同一个 3 通道掩码（仅 126 种）⇒ **动态掩码退化为静态掩码**。
- **有效维 ≫ 保留数**：h 侧 84~112 vs 3~38；FFN 中间 470~505 vs 10~154 ⇒ 截断过头 3~17 倍。
- **死神经元率全程 0**：不是"用不过来"，是"大家都用同一批"。
- **FFN 中间掩码几乎免费**：keep=5% 时裁与不裁 FFN 中间，loss 6.9033 vs 6.9038（差 0.0005），
  却省 2.6× FLOP ⇒ 伤害全部来自 h 侧截断（qkv / gate-up 的输入维）。
- 数值熵从初始化 0.949 降到 0.80~0.85（训练确实在集中数值分布），但**不随稀疏率缩放**。

### 6.5 结论（1M tokens、同协议）

1. 1~15% 激活率下，只有 **15% 在同 FLOP 下略胜**（−0.036，且稠密臂 FLOP 多 7%）；5% 转负（+0.083），1% 崩（+0.668）。
2. 质量优势的消失与"动态性消失"同时发生：top_share 0.33→0.85、n_pat 1651→126、jac 比值≈1。
3. 对比此前 2M tokens、keep=56.25% 的 −0.151（同 FLOP），**最优区间在中等稀疏（30~60%）而非极端稀疏**。
4. 若要把"按领域分配组合"做出来，必须阻止塌缩（负载均衡/熵正则、可学 router、显式组合分配），
   或者接受"近静态掩码"这一事实——那它就应该与静态剪枝/窄模型对比，而不是与"动态"对比。

指标定义：
- **稀疏熵 H_mask** = −Σ p_j log p_j / log d，p_j 为通道 j 的**全程累计**激活频次占比。
- **死神经元率** = 全程从未被选中过的通道比例（累计计数器）。
- **数值差异熵 H_val** = 每 token |激活值| 归一化分布熵；**有效维 = d^H_val**。
- **n_pat / pat_H / top_share** = 不同掩码个数 / 模式分布熵 / 最常见掩码占比（区分"领域组合"与"整体塌缩"）。
- **jac_w / jac_c** = 同序列内 vs 跨序列 token 掩码的 Jaccard（领域专用组合应 ≫ 1）。

### 6.3 速度：PyTorch 的 CSR 稀疏乘 vs 稠密 GEMM（4096 tokens，4 线程，已校验误差=0）

| keep | qkv/o (256→256) | gate/up (256→1024) | down (1024→256) | head (256→8198) |
|---|---|---|---|---|
| 15% | 2.44× | 1.46× | 2.37× | 0.89× |
| 10% | 1.69× | 1.07× | 3.50× | 1.29× |
| 5% | 4.14× | 1.96× | 6.87× | 1.60× |
| 2% | 7.35× | 2.14× | 10.98× | 1.76× |
| 1% | 8.50× | 1.53× | 20.71× | 1.52× |

- 高稀疏下**逐 token 的真稀疏乘确实比稠密快**；但 gate/up 与 head 受输出带宽限制，只有 1.5–2×。
- 选择开销是当前瓶颈：PyTorch topk ≈ 8.3 ms(d=256) + 25.6 ms(I=1024) 每层每步。
