# P27：SGD 为什么"应该有却没有" + zh_run1b 在狐娘数据上的 SFT

日期 2026-10-17 | 全部数字都来自本轮实测，未测项在 §7 明列。

---

## 0. 摘要

**问：上一轮 SFT 用的"维基预训练"是哪个文件？**
答：不是 `zh_run1b.cpk`。上一轮（P26 Track A）的 a2 臂载入的是
`_opt\p26\a0_pretrain\base.cpk` —— 它是**同一次运行里 a0 臂现训出来的**
checkpoint（dim512/L4/42.6 万参数的 toy，1500 步、58 s，语料 `artifacts\zh_wiki`）。
所以那一轮"预训练初始化让最终 CE 低 3.5%"是 **toy 级结论**，与真实维基模型（`zh_run1b.cpk`，
dim4096/L32/170 万参数、14296 步、val 4.9135）无关。本轮改用 `zh_run1b.cpk` 重做。

**问：SGD 是不是抽库没抽干净？**
答：是，而且是**很具体的一处**：引擎/ISA 侧一直有 SGD
（`core/src/train.rs:175 sgd()`、`trans/src/opcode.rs:62 OP_SGD`、`asm/src/main.rs:235` 的 `"SGD"` 助记符、
`core/src/interp.rs:594` 的执行分支），**但 `b1_full_train.rs` 这个驱动把优化器写死成 Adam**：
9 个参数更新点全部直接调 `adam_dense(...)`，命令行没有任何开关能选优化器 ——
抽库时抽走了 ISA/matmul/反向内核，**训练循环里的优化器分发留在了驱动里**。
本轮补上 `--optimizer 0|1|2|3`（adam / sgd / sgdm / 逐张量归一化 sgd），默认路径**逐位不变**。

三条硬结论：

| # | 结论 | 证据 |
|---|---|---|
| 1 | 纯 SGD 在 Adam 的 lr 下**完全学不动**，不是"没接上"，而是**步长单位不同** | 同 lr=1e-3：Adam val 6.0319 / SGD val 9.0106（=ln V，没学）；数值校验：同一步 ‖Δp_adam‖/‖Δp_sgd‖ = **11007×** |
| 2 | SGD **能**追上 Adam，但需要 lr 大 **300 倍**，且贴着发散边界 | sgdm lr=0.3：val **5.9857**（Adam 6.0319，好 0.77%）/ lr=1.0 **发散**；纯 SGD lr=1.0：6.5036 |
| 3 | "全局梯度尺度归一化"（RMSE 的 c 在优化器侧的等价物）**救不了 SGD** | `--lr-mode 1`（损失尺度自适应 lr）：8.981328 → 8.981331（相对差 **2e-6**，等于没变化） |

**狐娘 SFT**（`zh_run1b.cpk` + 8460 个 32+32 定长样本，160 步、0.61 epoch）：
留出集 CE **9.2660 → 5.3891（−41.8%）**，生成从"纯乱码（自评 9.8 bits/char）"变成
"林狐口吻的对话（自评 3.26 bits/char，含 `啊呜~`、`（尾巴…）`、轮间 `</br>`）"。

## 2. SGD 在哪、缺在哪

| 层 | 有没有 SGD | 位置 |
|---|---|---|
| ISA / opcode | 有 | `trans/src/opcode.rs:62` `OP_SGD = 68`；`asm/src/main.rs:235` `"SGD" => OP_SGD` |
| 内核 | 有 | `core/src/train.rs:175` `pub unsafe fn sgd(p,g,n,lr)`（`p -= lr*g`，无动量） |
| 解释器 | 有 | `core/src/interp.rs:594` 的 `OP_SGD =>` 分支 |
| **训练驱动** | **无** | `train/src/b1_full_train.rs` 原先把 9 个更新点全部写成 `adam_dense(...)`，`--optimizer` 参数不存在 |

本轮改动（全部在驱动侧，**没有新内核**）：

```
--optimizer 0|1|2|3   0=Adam(0.9,0.999) 1=SGD 2=SGD+momentum0.9 3=逐张量归一化SGD
--sft-from N          显式 prompt 长度（token 数）；N>0 时位置 t>=N 才计 CE/写梯度
                      （--sft 1 仍然等价于 seq/2，保留旧行为；但注意 seq/2 会漏掉第一个 response token）
```

- `1`：`p -= lr*g`，语义与 `core::train::sgd` 一致。
- `2`：`m = 0.9m + g; p -= lr*m`（复用调用点本来就在传的 `m` 缓冲当速度项；`v` 不用）。
- `3`：`g ← g/‖g‖_2; p -= lr*g` —— **Eq.8「分组归一化」在张量级的极限**，专门用来对照"全局标量"。
- 三者的梯度都先经过原有的逐张量 `clip_grad(…, clip)`。

**默认路径逐位不变的证据**（改了两次代码，测了两次）：
`o0_adam_base` 的 `loss_hash` = `0x373320f16bee8935`，与 P26 的 b0 完全相同，
`final_train=5.858808` 也逐位相同 —— 加 `--optimizer`（含 mode 3 分支）与 `--sft-from` 之后，
不传这些开关时的行为一个 bit 都没动。

## 3. 数值级校验：SGD 臂真的在跑 SGD 吗？

只比"loss 降了"区分不开"分发写反了 / m、v 没重置 / lr 没接进去"。所以直接比**参数位移向量**
（`_opt/p27_optcheck.py`，1 步、同一初始化、存盘后逐张量比对）：

| 判据 | 预期 | 实测 | 结论 |
|---|---|---|---|
| lr 线性性（lr 1e-3 vs 2e-3，同一步） | 每个张量 ‖Δp‖ 翻倍 | 在 f32 存盘噪声内（相对容差判据 `max[(ratio−2)/tol] = 0.002`） | PASS |
| SGD 步长标定 | ‖Δp‖/lr = ‖g‖ | 层：**5.809e-3 / 5.878e-3 / 5.736e-3 / 5.844e-3**，与 P26 实测层梯度范数 **5.66e-3**（`[gnorm] step=25`）吻合 | PASS |
| Adam 步长标定 | ‖Δp‖/(lr·√n) ≈ 1（逐元素步长 = lr） | 层：**0.9989 / 0.9988 / 0.9991 / 0.9989** | PASS |
| 同 lr 同一步的位移差 | Adam ≫ SGD | 第 1 个张量 **‖Δp_adam‖/‖Δp_sgd‖ = 11007×** | 这就是"学不动"的直接测量 |
| 动量首步等价 | sgdm 第 1 步 m=g ⇒ 与 SGD 第 1 步逐位相同 | `max|Δ差| = 0.000e+00` | PASS |

顺带发现（非本轮引入）：这一步里 `asq0/ask0/asq1/ask1`（稀疏注意力的 Q/K 投影）
**梯度恒为 0**，位移精确为 0 —— 即这 4 个张量在 `--attn-sparse 1 --attn-src-shared 1` 下不参与学习。
没深挖，记在这里以免被当成"优化器掉了张量"。

唯一变量是优化器与 lr。`final_val` 是留出集 CE，越小越好；`--eval-every 500`。

（`wall_s` 那一列没放进表：第三轮的计时被同期另一个训练任务污染（两个进程 `--pin 1` 抢同一批核），
按本项目既有纪律，**不做配对计时的结论**。）

### 4.1 为什么"同一 lr 学不动"是必然的（换算被实测证实）

实测层梯度范数（P26 `[gnorm]`）：step 25 时 **5.66e-3**，step 1500 时 **1.01e-1**。
层张量 4096 个元素 ⇒ 逐元素 |g| ≈ norm/64 = **8.8e-5 → 1.6e-3**。

- Adam 的逐元素步长 = lr = 1e-3（§3 实测列 ≈0.999）；
- 纯 SGD 的逐元素步长 = lr·|g| = 1e-3 × 8.8e-5 ≈ **8.8e-8**；
- ⇒ 要匹配 Adam，纯 SGD 需要 lr ≈ 1e-3/(norm/64) = **0.064/norm = 0.64 ~ 11**。

实测最优点正好落在这个区间附近：纯 SGD lr **1.0** 才接近 Adam，sgdm lr **0.3**（动量稳态把梯度放大
≈1/(1−0.9)=10 倍 ⇒ 等效 3.0）追平 Adam，而 sgdm lr 1.0 已经发散 —— **换算是对的**。
这也说明"给 SGD 调 lr"不是调参小事，而是**改步长单位**：lr 的有效量纲依优化器而变。

### 4.2 归一化到底解决了什么

| 方案 | 作用粒度 | 实测（同 lr=1e-1 附近） |
|---|---|---|
| `--lr-mode 1`（损失尺度自适应 lr） | **全局标量**（= RMSE 的 c） | 对 SGD 完全无效（8.981328 → 8.981331） |
| `--optimizer 3`（逐张量归一化） | **每张量一个标量** | lr 1e-1 → 6.8178，比纯 SGD lr 3e-1 的 8.2173 好，但仍差于 Adam 6.0319 |

结论直接对应 RMSE 的两种归一化：论文 Eq.5 的 `c = √N/(2‖r‖)` 是**一个全局标量**，
它只能整体缩放所有参数的步长（等价于改 lr），**不能改变逐参数步长比**；
Eq.8 的分组形式（每 M 组一个 `1/s_m`）才是**分组**标量，粒度更细 ——
上表说明粒度越细越有用，而"逐张量"仍不足以替代 Adam 的逐元素预条件。

### 4.3 SGD+mom 会让训练更快吗？（实测：不会；而且这个训练器不是 I/O 受限）

配置：dim4096/L32/batch32/seq64、4 线程 `--pin 1`、zh_wiki、`--profile 1`、60 步 × 2 轮**交错**。
（为什么用相位 7 而不是总步时：同一臂两轮总步时就能差 18%（冷启动页错误 + OS 缓存），
而相位 7 只累加训练循环内的时间，两轮之间只差 0.7%。）

| 臂 | ms/步（两轮） | 优化器相位（相位 7）ms/步 | 占实测步时 |
|---|---|---|---|
| Adam | 1396.7 / 1391.7 | **2.23** | 0.160% |
| SGD | 1393.3 / 1391.7 | 1.18 | 0.085% |
| SGD+mom | 1395.0 / 1373.3 | 1.70 | 0.122% |

- **总步时三臂无差别**（1384~1397 ms，跨臂 0.9%）。优化器相位本身确实接近减半
  （Adam→SGD **−47%**，Adam→SGDM −24%），但换来的是 **1.05 ms / 0.53 ms 每步**，
  即 **−0.075% / −0.038%** —— 低于这台机器的可信测量分辨率。
- **带宽模型能预测它**（说明三臂测的是同一个物理量）：Adam 28 B/参数（读 p,m,v,g + 写 p,m,v）
  + clip 8 B = 61.4 MB / 2.233 ms = **27.5 GB/s**；SGD 34.1 MB / 1.183 ms = **28.8 GB/s**；
  SGDM 47.7 MB / 1.700 ms = **28.1 GB/s** —— 三臂落在同一个带宽（±2.3%）⇒ 优化器相位**内存带宽受限**。
- **为什么它永远这么小**：优化器占总步时的比例
  `≈ 4.67·FLOPS_有效/(tokens_per_step · BW)`，与参数量 **P 无关**（分子分母都 ∝ P）。
  代入实测 11.5 GFLOPS、2048 token/步、28 GB/s ⇒ 0.094%（实测 0.160%，同量级）。
  所以"掉 m/v 让训练更快"在任何规模上都基本不成立；只有优化器状态被**换出/流式**
  （ZeRO-Offload 之类）、或 tokens/步 很小（batch=1 且不做梯度累积）时才进入"优化器主导"区。
  掉 m/v 真正值钱的地方是**内存容量**：Adam 状态 2P×4B = 13.6 MB（本配置）→ SGD+mom 只需
  P×4B = 6.8 MB，省一半；1.7M 参数下没意义，7B 参数下就是 56 GB（装得下 / 不换出的差别）。
- **那 99.8% 的时间在哪**（相位表按 nslot=4 摊平到 wall，已统计部分覆盖 93.4%）：
  逐层反向 **56.3%**、前向（`--sparse-io 1` 时相位 1 记的是**整段前向：嵌入+32 层+head**）**34.6%**、head 反向 1.0%、嵌入反向 1.0%、CE 0.4%、
  未统计 6.6%（含"逐层前向"这个计时点在本路径上没命中 + 取批/线程同步）。
  有效算力 = 16.1 GFLOP / 1.396 s = **11.5 GFLOPS**，约 4 线程峰值的 3%
  ⇒ 瓶颈是内核的**指令级/延迟效率**（稀疏 gather、小 tile、反向缺 AVX2 路径），
  不是 I/O 带宽，也不是算力峰值。
- **"我们已知是 I/O 瓶颈"这个前提在本训练器上不成立**：
  整个 60 步进程读盘 **143.2 MB = 启动时一次性读入的语料**，训练中每步增量 **0**；
  平均忙核 **3.10 / 4**（真在等磁盘的话会远低于线程数）；
  逐层反向 + 整段前向两个计算阶段占了 90.9% 的 wall。

## 5. 狐娘 SFT（zh_run1b → `artifacts\fox_sft`）

### 5.1 数据（`_opt/fox_prep.py` / `_opt/fox_verify.py` / `_opt/fox_report.md`）

源：`这是数据集但是格式要转换.jsonl`（150 条 turns 对话）。用 `artifacts/zh_wiki/char_vocab_hex.txt`
（8198 字，与 `zh_run1b` 同一张表）编码，**不能重新统计字频**，否则 embedding 行号对不上。

- 布局：每个 64-token 训练样本 = **32 prompt + 32 response**，`--sft-from 31` ⇒ 位置 31..62 共 32 个 CE，
  正好预测窗口内第 32..63 个 token（全部 response）。样本背靠背，`train_ids.bin = 64*8460+1`（末尾 1 个哨兵）。
- 切分：**按对话** 130/20（不按 token，避免泄漏）；`val_ids.bin = 92606` token 的连续文本流。
- 数量：8460 个训练样本；assistant 回复长度 min18 / mean67.4 / p50 66 / p90 96 / max141 token；
  丢弃 126/8586 个凑不满 32 的尾窗口（1.47%，response token 的 0.68%）；跨 assistant 轮的窗口 45.56%（已知偏差）。
- **OOV 硬上限**：response 段 1.2053% 的目标 token 是 `<unk>(0)`。Top-1 就是 **「嗷」（源数据 4202 次，占 OOV 的 63.5%）
  不在词表里** ⇒ 模型**永远生成不出"嗷呜"**，只能给 `呜` 或 `<unk>`。下文生成样例里 `<unk>呜~` 正是这个位置。
- ⚠️ **对齐陷阱（这轮差点静默错 15%）**：驱动取批是 `cursor = (seed*977) % (len−seq−1)`，
  `977 ≡ 17 (mod 64)` ⇒ `--seed 1` 时每个窗口整体平移 17 个 token，"32/32"边界全错；
  实测错位探针（`--seed 1`、batch16）的首步 train CE 是 7.93，对齐后（`--seed 64`、batch32）是 9.24 —— 差 1.3，方向与"prompt 段比 response 段好预测"一致（两臂 batch 不同，只作警示，不作定量结论）。
  已在驱动里加断言（`--sft-from>0` 时要求 `(len−seq−1)%seq==0` 且 `cursor%seq==0`），
  并做了 can-fail 验证：`--seed 1` → `FATAL … 请令 seed 为 64 的倍数`；`--seed 64` → 正常跑。

### 5.2 结果（160 步 = 0.61 epoch，batch32，seq64，warmup10，cosine→1e-5，clip 1，seed 64）

`a0` 是**未训练**基线（`--lr 0 --steps 1`，权重逐位不动）：
val CE **9.2660** —— 比均匀分布 ln V = 9.0116 **还差**，即维基模型在狐娘领域是"负知识"状态。

| 臂 | lr | 掩码 | final_train | **final_val** | 相对基线 |
|---|---|---|---|---|---|
| a0 未训练 | 0 | 31 | 9.2428 | 9.2660 | — |
| a1 | 1e-4 | 31 | 8.7797 | 8.7029 | −6.08% |
| a2 | 3e-4 | 31 | 7.9923 | 7.6925 | −16.98% |
| a3 | 6e-4 | 31 | 6.8700 | 6.4702 | −30.17% |
| a6 | 1e-3 | 31 | 6.3920 | 5.9919 | −35.33% |
| a7 | 2e-3 | 31 | 6.0106 | 5.5819 | −39.75% |
| **a9** | **4e-3** | 31 | 5.8264 | **5.3891** | **−41.84%** |
| a4 | 3e-4 | 无 | 8.0157 | 7.6860 | −17.05% |
| a8 | 1e-3 | 无 | 6.3900 | 5.9626 | −35.64% |
| a5 | 3e-4（逐张量归一化 SGD） | 31 | 9.2127 | 9.2464 | −0.21% |

三点必须同时讲清楚：

1. **lr 越大越好，160 步内没出现转折**（1e-4→4e-3 单调下降到 5.39）。原因是起点太差（9.27 > 均匀分布），
   需要大位移才能离开；4e-3 是测过的最大 lr，**再往上没测**（见 §7）。
2. **掩码 vs 不掩码在同一 lr 下几乎一样**：3e-4 时 7.6925 vs 7.6860（+0.08%），1e-3 时 5.9919 vs 5.9626（+0.49%）。
   因为 val 指标是**未掩码的文本 CE**（位置 31..62 的 plain text），它衡量"领域适配"，不衡量"回复质量"；
   掩码的收益不体现在这个指标上，而体现在"只有 assistant 段拿到梯度"。**别把这个差值解读成"掩码没用"**。
3. **逐张量归一化 SGD 在 lr 3e-4 下等于没学**（9.2464）：归一化后的逐元素步长是 `lr/√n`
   （层 n=4096 ⇒ 3e-4/64 = 4.7e-6），比 Adam 的 3e-4 小 64 倍 —— 又回到 §4.1 的"单位错配"。

### 5.3 生成对比（同一 prompt、同一 seed=64、同一采样参数，best-of-4 按自评 bits/char）


## 6. 与 RMSE 那套结论的关系（本轮新增的部分）

已确立（前一轮，独立数学验证）：`g_RMSE = c·g_MSE`，c 是**全局标量**；Adam/AdamW 对 `g→c·g`
**不变**（rel diff 3.0e-5）⇒ "RMSE 损失 + AdamW ≈ no-op"。

本轮把这条结论在**一阶优化器**上补齐了：

- 全局标量 c 对 SGD 也只是一个乘在 lr 上的系数（`p -= lr·c·g`），实测 `--lr-mode 1` 在 SGD 上
  **一点用都没有**（8.981328 → 8.981331）—— 因为它的作用对象是"所有参数共用的一个标量"，
  而 SGD 学习不动的根因是"**逐参数的步长比**差 1~4 个数量级"（§3 的 11007×）。
- 把归一化做到**张量粒度**（`--optimizer 3`）就开始有用（8.22 → 6.82），但仍追不上 Adam。
- 所以要"让 SGD 可用"，缺的不是 RMSE 的全局 c，而是**逐元素/逐组的预条件**；
  论文 Eq.8 的分组形式比 Eq.5 的全局形式更接近"有用"的那一侧，但它的组是"输出维度/通道"，
  不是参数张量里的每个元素 —— 这也是它在 PTQ 场景里"能平衡各层梯度、但不等价于 Adam"的原因。

## 7. 未测 / 边界（不做无证据的外推）

1. **单 seed**。两处确定性已实测：同一配置重跑 `loss_hash` 逐位相同（`0x373320f16bee8935` 复现两次，
   含加 mode-3 分支之后）；`zh_run1b` 载入后 `param hashes` 与 summary 三个值全同。但**没有跨 seed**，
   所以"sgdm 0.3 比 Adam 好 0.77%"只能算"同一随机流下的一个点"，不是统计结论。
2. **规模**。Track B 全部在 dim512/L4/1.5M token、1500 步的 toy 上；Track A 在 1.7M 参数的模型上。
   大模型上"sgdm 需要 lr×300"这个比例会随 ‖g‖ 变化，不能外推。
3. **SFT 的 lr 没扫到顶**：4e-3 仍在下降，5e-3/1e-2 未测；也没测"训练更久"（160 步 = 0.61 epoch）。
4. SFT 只测了从 `zh_run1b` 初始化，**没有从零**的对照臂（上一轮 toy 级对照不能代表）。
5. val 指标是留出狐娘文本的 CE（位置 31..62），**不是**人工/模型评审的回复质量；掩码的收益在这个指标上看不出来。
6. 没有测 SFT 后的**灾难性遗忘**（wiki 上的 CE 未回测），需要另一次 `--data-dir artifacts\zh_wiki` 的评测。
7. **速度**：优化器相位已做交错配对计时（§4.3，60 步 × 2 轮，相位 7 两轮差 0.7%），
   所以"优化器省 1.05/0.53 ms 每步"是可信的；但**总步时**差异仍在噪声内（跨轮漂移 1.6%），
   即"总训练时间不变"是"没有证据表明有变化"，不是"证明了恰好为 0"。第三轮扫描的 `wall_s` 被并行任务污染，未使用。
   另：分阶段表里"逐层前向"这个计时点在生产路径上没命中（表里 0.000 s），前向的耗时只落在 6.6% 的未统计里，
   所以"逐层反向 56.3% / head 前向 34.6%"是可信的子项，而**前向/反向的完整拆解还缺一块**。
8. `asq/ask` 四个张量梯度恒 0 的现象只记录，未定位（可能是 `--attn-src-shared` 的设计，也可能是漏了反向项）。
9. 生成样例只跑了 2 个 prompt、best-of-4；"像不像林狐"没有客观评分，只有自评 bits/char 和模式计数。
