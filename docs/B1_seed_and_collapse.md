# 关于「只有 seed 1 能正常输出」的实测结论

## 一、这不是 seed 的 bug，是**模式坍塌 + 长尾**

用你的新模型 `artifacts\01.cpk`（dim4096/k0 8/k0e=h16/L32，**2,291,744 参数**）实测，prompt=`今天`，gen_len=100：

| 采样设置 | 不同字数 | 去重率 | 最多出现的字 |
|---|---|---|---|
| seed=1 temp0.7 k30 p0.85 | 35 | 0.354 | `晶`×52 |
| seed=2 temp0.7 k30 p0.85 | 88 | 0.880 | `找`×7（几乎每字都不同＝乱码）|
| seed=3 temp0.7 k30 p0.85 | 64 | 0.640 | `遽`×26 |
| seed=4 temp0.7 k30 p0.85 | 3 | 0.030 | `崽`×98 |
| **seed=4 k=1（贪心）** | **1** | 0.010 | **`天`×100** |
| seed=2 temp0.5 k20 p0.9 | 43 | 0.430 | `密`×27（降到 0.5 也没救）|

原文（节选，全文见 `artifacts\gen\SEED_REPORT.md`）：
* **seed=1（你说的"正常"）**：`亮晶晶晶晶…（52 个晶）…的尾巴，你的！啊呜~那我这就把茶香的，我一起来，尾巴，我这样子，我可要是小尖！（耳朵轻晃着月`
  ⇒ **前 ~30 个字是连贯语料风格，然后塌成单字循环** ✓ 这就是"看起来正常"的原因
* seed=4：`幺师崽崽崽崽…`（98 个崽）
* 贪心 k=1：`天天天天…`（100 个天）

**判据**：贪心解码走到 **1 个不同字** ⇒ 模型的 argmax 路径是个**环** ⇒ 典型的**模式坍塌**；
seed 2/3 出现 88/64 个不同字 ⇒ 模型**长尾几乎均匀**（没学会压掉生僻字）⇒ 采样在尾部乱走。
"只有 seed 1 能用" = seed 1 恰好在**塌之前多走了几十步好文本**，不是它的 RNG 有什么特殊。
（也说明 sampler 的 seed 接线是好的：不同 seed 输出确实不同。）

**降温/降 top-k 不能解决**：temp0.5+k20 仍然循环（`密`×27）⇒ 环是强吸引子。

## 二、"有空间未利用"这句：对一半

| 配置 | 参数量 |
|---|---|
| 你的新配置（k0 8 / k0_embed 16 / k0_head 16 / k0_attn 8 / L32 / dim4096）| **2,291,744** |
| 对照（k0 32 / k0_embed 128 / k0_head 128 / k0_attn 32 / L32 / dim4096）| **9,945,344** |

**4.34× 参数、loss/PPL 几乎不变** ⇒ k0 / k0_embed 这几个维度确实**严重冗余**（大配置里约 **77% 的这部分参数是浪费**）✓
**但采样现象不是"空间未利用"的证据**：有富余容量的模型采样会**更好**，而这里表现为**贪心成环** ⇒ 是**训练不足 / 坍塌**，不是容量过剩。

两个概念要分开：
* **参数冗余**（结构维度用不满）→ 由你这个 k0 对照实验证明 ✓
* **分布坍塌/长尾**（训练/优化问题）→ 由贪心 1 字循环 + 88 个不同字的乱码证明 ✓
* 顺带一个可检验的猜测：把 `k0_embed/k0_head` 从 128 砍到 16，**val loss 不变**，但 embed/head 是"隐状态→字表"的唯一通路，
  它变窄会**让尾部更塌**。要验证很简单：同一步数下比 **k0e=16 vs k0e=128 的生成文本质量**（不是比 val）。

## 三、一个重要更正：你测的那个 EXE 里不是 `01.cpk`

`dist\vmlm-chat-1.24m.exe` 内嵌的是 **dim1536 k0 8 k0e 32 k0h 32 L24 = `b1_char_10k_seq64.cpk`（979,008 参数）**，
不是你的新 `01.cpk`。所以你在 EXE 里看到的 seed 现象是**旧模型的**；上表是我用 `01.cpk` 直接跑 `--generate` 复测的。
（旧模型那次的表现：seed1 连贯→`呜~`循环、seed2/3/4 乱码、贪心 `乔醮育绥蝣`×N —— 同一类坍塌。）

## 四、建议（按性价比排序）

1. **给采样器加 repetition penalty 或 no-repeat-ngram**（约 15 行：改 `sample_next` + chat 参数）
   ⇒ 最直接地让**每个 seed 都能输出**，不用重训。
2. **用 `01.cpk` 重新打单文件 EXE**（一条命令；我可以顺手把 penal 也放进 chat 的默认参数）。
3. **训练端治本**：更长训练 / 末期 LR 再低 / 确认是不是被 plateau 早停掐掉了（坍塌常见于"还没学到抑制重复就停了"）。
4. 可选：`min-p` 采样、`--gen-greedy` 开关（便于快速看 argmax 质量）。

**(iii)** 跑一次"k0e=16 vs k0e=128 的生成质量对照"（同步数，比生成文本）。
