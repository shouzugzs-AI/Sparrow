# best-of-K 已实现（`--n-candidates K`）—— 机制可用，但**选择准则是关键**，且它救不了"整批都烂"

## 一、实现（只动生成路径，不碰内核/训练/intra）

| 位置 | 改动 |
|---|---|
| 驱动器 `--generate` | 新增 `--n-candidates K`（默认 **1**，保持旧行为）。K 条候选各自**独立随机流**（`seed + k*黄金比`）从 prompt 重采一遍 |
| 自评 | 新增闭包 `score_ids(&[u32]) -> bits/char`（按 seq 切窗跑同一条前向），生成端与 `--score-file` **共用** |
| 选择 | 见 §三（两轮修正后的准则）；结果与各候选明细都打印并写入输出文件头 |
| chat / 单文件 EXE | 新增 `n=K`（提示符里可改），**默认 4**；`n=1` 关闭 |

## 二、机制验证（K=4 确实能救回"坏种子"）

| 运行 | 各候选自评 bits/char | 选定 |
|---|---|---|
| K=1 seed 1（旧行为）| 2.900 | 2.900（**逐位不变** ✓）|
| K=1 seed 2 | 10.000（乱码）| 10.000 |
| **K=4 seed 2** | 10.000 / **6.373** / **6.308** / 9.790 | **6.308 = 正常样本水平** ✓ |

即：同一个模型、同一个 seed，**多抽 4 条就能捞到一条 6.3 bits 的正常样本**（K=1 只有 10.0 的乱码）。

## 三、过程中发现并修掉的两个"准则陷阱"（重要）

1. **纯自评 bits/char 会选中复读** —— 循环是最可预测的，NLL 最低。第一版 best-of-4 因此选中了 `逛逛逛…`。
   ⇒ 加"不是复读"的约束。
2. **去重率太弱** —— 一段 60% 是"谢"的文本仍有 ~40 个不同字，照样过 0.25 的门槛。
   ⇒ 换成 **最频繁 4-gram 覆盖率 ≤ 0.5**（复读文本接近 1，正常文本很小）。

最终准则：
```
① 自评 ≤ 8 bits/char  且  最频繁4-gram覆盖率 ≤ 0.5  →  取自评最低者（合格候选）
② 若没有合格候选  →  取"重复度最低、其次自评最低"的那条（复读 100% 无信息，乱码至少还有信息）
```

## 五、诚实结论

* **best-of-K 能做的**：在"存在好候选"时把好候选挑出来（seed 2 的 10.0 → 6.3 ✓）；并且**避免选中整体复读**（seed 5 ✓）。
* **best-of-K 做不到的**：**凭空造出质量**。当 K 条全是乱码时（seed 2），它只能选"最不坏"的那条 ⇒ 输出仍是乱码。
  换句话说：**多抽只能改变"选中哪条"，不能改变"分布里有没有好东西"**。
* 所以真正让"**每个 seed 都能用**"的两条路仍然只有：
  1. **采样期 repetition penalty / no-repeat-ngram**（改变分布，而不是事后筛选）——这是最直接的；
  2. **训练更多步**（让分布本身变好；你的 val 6.53 说明方向对，但自由生成的自评方差说明还没训够）。
* 已就绪的配套工具：`--score-file`（给任意文本打 bits/char，~6-7 = 可读、11+ = 跑出分布）、候选自评打印、
  `n=K` 交互参数 ⇒ 以后换模型/换训练配置，可以**用它做客观验收**而不是肉眼。
