# P62 状态向量模型落进引擎（`.s5q` + `vmlm-ssm` 推理路径）

> P61 证明「选择性 SSM 状态替代 KV」在质量上成立（seq128 4.0434 / seq4096 4.4150），
> 但那些数字都来自 PyTorch 训练器。本文把它做成**能跑的引擎侧推理**：
> 导出格式 + Rust 推理程序 + 与 PyTorch 的逐段对拍 + 性能优化实测。

## 0. 结论先行

| 项 | 结果 |
|---|---|
| 数值一致性 | prefill：64 token × 8198 词表，logits 最大绝对差 **1.5e-5**，argmax **0/64** 不一致 |
| 数值一致性（decode 路径） | prefill 32 + 逐 token 32，最大绝对差 **1.3e-5**，argmax **0/32** |
| prefill 吞吐（单线程） | ctx 128 → **2531 tok/s**；1024 → **3545**；4096 → **3627** |
| decode 吞吐（单线程） | f32 **3.22 ms/token（310 tok/s）** → bf16 **1.95（514）** → **int8 1.37（731）** |
| 对照：PyTorch 同模型单线程 decode | **4.06 ms/token（246 tok/s）** ⇒ 引擎 int8 快 **2.97×** |
| 量化代价（val CE，4×32 验证批） | bf16 **−0.00005**；int8 每行 scale **+0.000077**（都在噪声里） |
| decode 常驻内存 | 状态 **1 KB**，与 ctx 无关（KV 在 ctx=8192 是 16 MB fp32 / 4 MB int8） |

生产配置：**prefill 用 f32，decode 用 int8 权重**（每行一个 scale），质量代价 +7.7e-5 CE，
吞吐 731 tok/s；要绝对可复现就用 `--bf16` 或默认 f32。

## 1. 交付物

| 文件 | 作用 |
|---|---|
| `tools/p68_export_ssm.py` | 把 p36 的 ckpt 导出成 `.s5q`（含 PyTorch 参考 logits，按 tag 命名） |
| `tools/p69_ssm_dump_ref.py` | 用 forward hook dump 各层中间量，供引擎逐段对拍 |
| `train/src/ssm_run.rs`（bin `vmlm-ssm`） | 引擎侧推理：加载 / prefill / decode / 采样 / 对拍 / 测速 |
| `artifacts/ssm/<tag>.s5q` | 模型文件（44.8 MB，11.74M 参数） |

`.s5q` 格式（小端，故意不用 JSON，Rust 侧零依赖解析）：

```
magic  b"S5Q1"
u32    d, layers, vocab, hidden, attn_every
u32    n_tensors
n_tensors × { u32 name_len, name, u32 off(以 f32 计), u32 numel }
f32 × 全部张量（按上面顺序）
```

## 2. 前向对照（这是最容易做错的地方）

引擎里的前向必须逐字对齐训练器 `DynLM.forward` + `Block.forward`：

```
x  = emb(tok)
x0 = rmsnorm(x, ln0)          A = ssm_scan(x0)          # 每 attn_every 层刷新一次，本模型只刷新 1 次
for li in 0..L:
    x += inj[li] * A          # ← 每一层都注入，不是只在刷新层！
    h  = rmsnorm(x, ln1[li])
    x += down(silu(gate(h)) * up(h))
xn = rmsnorm(x, norm);  logits = xn @ embᵀ
```

**踩到的两个坑（都靠逐段对拍抓出来，不是靠看代码）**：

1. `up` 的输出缓冲按 `d` 分配、实际写 `I` 个数 → 越界覆盖（第一层就炸）。
2. `inj` 注入原来是**每层**做（A 只在刷新层重算），我一开始只在刷新层注入 → 从第 1 层开始分叉。

逐段对拍（`--dbg`，脚本 `tools/p69_ssm_dump_ref.py` 用 forward hook 取真值）留下的证据链：

```
x0    最大差 0.0e0        （embedding 一致）
A     最大差 1.9e-5        （状态混合器一致）
h0    最大差 2.1e-6        （norm + 注入一致）
act0  最大差 6.3e-5        （gate/up GEMM 一致）
d0    最大差 1.4e-4        （down GEMM 一致）
blk11 最大差 6.7e-4
logits 最大差 1.2e-5
```

## 3. 性能：先修一个大坑，再做量化

### 3.1 第一个坑：AVX2 没被打开

`ops::gemm_nt` 只有在 `vmlm_core::interp::HAS_AVX2` 为真时才走 8×8 向量内核，
否则**静默退回标量**（没有任何报错）。引擎启动时漏了 `init_cpu()`：

| | prefill ctx=64 | decode |
|---|---|---|
| 漏 `init_cpu()` | 196 tok/s | 299 tok/s |
| 加上之后 | **1964 tok/s** | 312 tok/s |

10× 的差距，而且不会失败——这类"静默降级"必须靠测速发现。

### 3.2 量化：decode 是纯带宽瓶颈

decode 每 token 要流 12 层 × 3 矩阵（36 MB）+ 词表头（8.4 MB）≈ 44 MB，单核 DRAM 带宽只有
10–13 GB/s，所以 f32 下 3.2 ms/token 已经贴着带宽上限。量化直接减流量：

| 权重精度 | 每 token 流量 | decode | 相对 f32 | val CE 变化 |
|---|---|---|---|---|
| f32 | 44 MB | 3.22 ms（310 tok/s） | 1.00× | — |
| bf16 | 22 MB | **1.95 ms（514 tok/s）** | **1.66×** | −0.00005 |
| int8（每行 scale） | 11 MB | **1.37 ms（731 tok/s）** | **2.35×** | +0.000077 |

- 量化只用于 **decode**（T=1）；prefill 仍用 f32 的 `gemm_nt`，因为 `gemm_nt_bf16` 没有打包复用、实测更慢（45 ms vs 33 ms）。
- int8 的 argmax 在 32 个 decode 步上 **0 不一致**；CE 代价 +7.7e-5 与噪声底（0.098）差三个数量级。

### 3.3 prefill 随 ctx 变快（权重被摊薄）

| ctx | 时间 | 吞吐 |
|---|---|---|
| 128 | 50.6 ms | 2531 tok/s |
| 1024 | 288.9 ms | 3545 tok/s |
| 4096 | 1129.2 ms | **3627 tok/s** |

decode 与 ctx 无关（状态常数），这是这条架构最直接的卖点：**没有 KV cache 要增长**。

### 3.4 与训练框架的对照

同一份权重、同一台机器、单线程：

| | decode |
|---|---|
| PyTorch 训练器（单线程） | 4.06 ms/token（246 tok/s） |
| 引擎 f32 | 3.22 ms（310 tok/s） |
| 引擎 int8 | **1.37 ms（731 tok/s）** |

## 5. 复现

```bash
# 1) 导出（同时产出 PyTorch 参考 logits）
python tools/p68_export_ssm.py --tag st_ssm_lr4e3_4000
python tools/p68_export_ssm.py --tag st_ssm_seq4096_lr4e3_2000

# 2) 逐段参考（可选，排查用）
python tools/p69_ssm_dump_ref.py --tag st_ssm_lr4e3_4000

# 3) 引擎
cargo build --release --bin vmlm-ssm
./target/release/vmlm-ssm --model artifacts/ssm/st_ssm_lr4e3_4000.s5q --check          # f32 prefill 对拍
./target/release/vmlm-ssm --model artifacts/ssm/st_ssm_lr4e3_4000.s5q --check-decode   # decode 路径对拍
./target/release/vmlm-ssm --model artifacts/ssm/st_ssm_lr4e3_4000.s5q --dbg            # 逐段对拍
./target/release/vmlm-ssm --model artifacts/ssm/st_ssm_lr4e3_4000.s5q --speed --int8    # 吞吐
./target/release/vmlm-ssm --model artifacts/ssm/st_ssm_lr4e3_4000.s5q --gen --len 60
```

## 6. 限制

1. **这不是 `runtime`/`.vmb` 那条 no_std 路径**：`vmlm-ssm` 是 std 二进制（与 `dist/vmlm-chat-*.exe` 同一血脉），
   没有走 `core::interp` 的 VM/`.vmb` 格式。要打进"零依赖单 exe"还需把权重嵌进二进制（`include_bytes!`）并接词表。
2. **单线程**：`gemm_nt` 的线程化没开（prefill 有 4 核可用，理论上还能再快 2–3×）。
3. **int8 只做了解码侧**，prefill 仍 f32；混合精度会让 prefill 与 decode 的数值有 ~1e-2 的 logits 漂移（argmax 不变）。
4. 生成质量受模型规模限制，本文只主张"链路正确 + 速度"，不主张生成可用。
