# P20：指令级审计（AVX2 / FMA 利用率）+ source-major（t8）结构性验证

审计方法、逐条结论、以及「B1 稀疏 = 稀疏拓扑/稠密计算」这条判断的**量化检验**。

## 0. 方法与工具

```powershell
# ① 带符号 release（供 dumpbin 看真实指令）
cargo rustc --release -p vmlm-train --bin vmlm-b1-full -- -C strip=none
"C:\...\BuildTools\VC\Tools\MSVC\14.44.35207\bin\Hostx64\x64\dumpbin.exe" /disasm /nologo target\release\vmlm-b1-full.exe > _opt\dis_train.txt
# ② rustc 直出 asm（可按函数/内层循环统计；LTO 版才有跨 crate 内联）
cargo rustc --release -p vmlm-core  --lib  -- --emit=asm          # core 内核
cargo rustc --release -p vmlm-train --bin vmlm-b1-full -- --emit=asm   # 6.7 MB，含内联后的热循环
# ③ 统计脚本
python _opt/asm_audit2.py  target/release/deps/vmlm_b1_full.s --func <name> --top 8   # 内层循环构成 + 打印循环体
python _opt/asm_hist.py    target/release/deps/vmlm_b1_full.s <name> 16               # 单函数助记符直方图
python _opt/asm_dump.py    target/release/deps/vmlm_b1_full.s <name> 220              # dump 整个函数
```

分类：**A** 已用 FMA/AVX2 正确 · **B** mul+add 未合并 FMA · **C** 128 位未升级 256 位 ·
**D** 标量浮点循环 · **E** 其他（例如每次调用重算常量）。

「每步重算的 Adam 常量」，逐条实测后**要么无收益、要么收益低于噪声**（§2）。

## 3. 「稀疏拓扑 = 稠密计算」的量化检验（本轮最重要的发现）

**你的判断在指令层面成立，我先量化它，再用实验检验它在真实训练里能不能兑现。**

### 3.1 指令层面：B1 每条连接的成本 vs 同 MAC 稠密

`kbench` 实测（i3-12100F，4c/8t，单线程）：

| 路径 | ns/连接 | cycles/连接 | 每 8 个 MAC 的 uop 数（估算） |
|---|---|---|---|
| 发布版 B1 前向（gather + 8 路归约） | 0.1766 | 0.583 | ≈9（1×gather + 3 vec + 横向归约 4） |
| **source-major(t8) 前向**（连续 32B load + FMA） | **0.0967** | **0.319** | ≈2 |
| 同 MAC 稠密理想（2×FMA/cycle，8 lane） | 0.0313 | 0.0625 | ≈0.5 |
| 发布版 fused 反向 | 0.6625 | 2.19 | ≈47（1/8 gather + 4 dw + 8×5 dx 标量散写） |
| **t8 反向**（dw 做 t 维点积 + dx 连续 RMW） | **0.3007** | **0.99** | ≈8 |

⇒ 前向离稠密理想 8.4x、反向离稠密理想 16x，差距**全部**来自
「`vpgatherdps`（8 lane 一次）+ dx 无 scatter 只能 8 条标量 RMW」——
这正是你在指令层面指出的那件事，也说明「逐序/逐块（source-major）计算」确实能把前向拉到 2 uop/8MAC。

### 3.2 落地实验：drop-in t8（每层转置两次/三次）

我把这条思路实现成**不动任何调用方布局**的 drop-in 内核（`b1_layer_forward_t8` /
`b1_layer_backward_t8`：转置 → source-major 内核 → 转置回），并做了逐值对拍与端到端实测：

* 正确性：`kbench --mode t8check`（n=2048,k0=8,t=128）→ dw 比值 **1.0000**（maxdiff 1.7e-6）、
  dx 比值 **1.0000**（maxdiff 3.6e-7），AVX2 反置与标量反置逐值一致；
  trainer `--gradcheck 1 --t8 1` → **PASS 40 探针 / 越界 0**。
  （过程中抓到并修掉一个真 bug：AVX2 的 dx 更新误用了 `x0` 而不是 `y0`，gradcheck 报 ana 比 FD 大 ~300 倍，
  dw 却是对的 —— 这类「解析梯度系统性偏大」正是 gradcheck 存在的理由。）
* 单点性能（kbench，含转置）：前向 **1.83x**、反向 **2.20x**。
* **接进 trainer（primary 100 步，同一时段背靠背）**：

| 组合 | s/步 | 相对 |
|---|---|---|
| 关闭（基线） | **0.1587** | 1.00 |
| 只开前向 | 0.1864 | 1.17 |
| 只开反向 | 0.2115 | 1.33 |
| 全开 | 0.2272 | 1.43 |

  纯 B1 栈（关掉注意力，形状与 kbench 完全一致）单独复测：**0.1041 → 0.1635 s/步（1.57x 慢）**。
* **诊断**：drop-in 每层要额外付 2–3 趟 `[t×d]` 转置（≈2–6 MB/层/region 的读写），
  而 trainer 是**带宽受限**、不是指令受限（12 层激活 `h_ins` + 注意力缓冲已经把内存系统压满，
  8 个 region 抢 4 物理核）。单线程 kbench 里 1 MB 的转置 L2 常驻、几乎免费，
  于是「指令级 8x 优势」在真实并发下被转置流量吃光还倒亏。
* **处置**：默认关闭（`--t8 0`），内核与对拍脚本保留。
* **下一步（要真正兑现，必须做的唯一一件事）**：让布局**在整条栈上**都是 source-major ——
  即 `h_ins`/`dy`/`dx` 全部存 `[d][t8]`，只在「嵌入 → 第 0 层」「第 L 层 → head/attention」
  这两处边界转置（每步 2–5 次，而不是现在的 27 层 × 2–3 次）。
  按本次实测外推：转置流量降到 1/10 后，前向/反向应各拿到 1.6–2.0x，
  端到端 ≈ **−30%**（逐层反向占 53%）。这需要改 `step_fn` 的 region/slot 缓冲与注意力边界，
  属于「布局改造」而不是「指令改造」，风险与工作量都高，本轮未做（留档）。

### 3.3 与稠密对照的诚实结论

* 「B1 = 稀疏拓扑 + 稠密计算」这条**在数学上完全成立**（无 top-k、无跳过，k0 条全算），
  所以「应与同参数稠密同速或更快」**在指令吞吐口径上是可达的**（前向 2 uop/8MAC vs 稠密 0.5）。
* 但本 trainer 的当前瓶颈**不是指令**：8 线程下每步内存流量（12 层激活 + 注意力 5 份 qkvo +
  head 0.5 MB 权重多次读改写）已经把带宽吃满。**在这个瓶颈下**，gather 版本（一趟、原地）
  反而比 source-major（多两趟转置）更快 —— 这是 3.2 实测出来的，不是推理。
* 因此要同时满足「指令级最优」和「不增加流量」，只有 §3.2 的整栈布局改造一条路。

## 4. 本轮改动的净效果与红线

* 代码净变化：`core/src/kernels.rs` 新增 t8 反向内核 + 反置转置 + 详细注释；
  `core/src/b1_pure.rs` 新增两个 drop-in 包装；trainer 新增 `--t8/--t8-fwd/--t8-bwd`（**默认关**）
  与 thread-local scratch；`core/examples/kbench.rs` 新增 `t8check`/`t8bwd`/`t8_back`。
* 默认路径性能与 P19 收盘一致（primary 100 步 **0.1686 s/步**，生产 12 步 **1.2358 s/步**）；
  FMA 实验已回退，所以默认路径**没有任何数值变化**。
* 红线：`--gradcheck 1`（稀疏 + 稠密）**PASS**；`vmlm-tests.exe` **全部 PASS**；
  本轮所有端到端运行 **无 NaN、无 0xC0000005、loss 单调下降**（9.01232 → 9.00347）。
* 收官实测（默认路径，t8 关闭）：primary 100 步 **0.1686 s/步**（min 0.1605）；
  生产 dim4096/L32/batch32 12 步 **1.2358 s/步**（min 1.2239）—— 与 P19 收盘同档，无回退。
* 复现：
  ```powershell
  cargo build --release -p vmlm-core --example kbench --features train,conn-sparse
  .\target\release\examples\kbench.exe --mode t8     --dim 2048 --k0 8 --t 128 --rep 40   # 前向 1.83x
  .\target\release\examples\kbench.exe --mode t8bwd  --dim 2048 --k0 8 --t 128 --rep 30   # 反向 2.20x
  .\target\release\examples\kbench.exe --mode t8check --dim 2048 --k0 8 --t 128           # dw/dx 逐值对拍
  python _opt\asm_audit2.py target\release\deps\vmlm_b1_full.s --func attn_core_row --top 8
  ```
