# P32：B1 稀疏 vs 真正稠密 —— 等 MAC / 等 token / 等墙钟三方对照

状态：**完成**（三臂全部跑完，均为实测）。原始日志在 `artifacts/p32/`
（本机生成物，不进版本库；§7 的命令可原样重建）。

## 0. 结论

1. **等墙钟（同样 36–39 分钟）：稠密 d=64 赢 0.63 nats**（val 5.263 vs 5.891，PPL 193 vs 361）。
2. **等 token / 等 MAC：B1 只领先 0.08–0.12 nats**，即**基本打平**。
   项目里此前"18/18 稀疏等 MAC 全胜稠密"的数字是 **head 宽度口径**造成的（见 §1）。
3. 两个口径的差就是**每-MAC 效率差 4.2×**：B1 10.0 GMAC/s、稠密 d=64 41.8 GMAC/s。
4. **换算**：等墙钟下 B1 只有 2.78M token，稠密有 11.06M token。要打平，
   B1 的"等 token 质量优势"需要从 0.084 nats 提高到 ≈0.71 nats —— **差 8.5 倍**，
   不是靠调一个 k0 能补的。

## 1. 为什么必须重做这个对比

| 现有证据 | 问题 |
|---|---|
| `B1_结果报告` §3：稀疏 val 7.332 vs 稠密 7.695（300 步） | 稀疏 474.8 s / 稠密 39.0 s；等墙钟稠密能跑 3650 步，比的是瞬态 |
| `B1_scaling_law`：18/18 "等 MAC 胜稠密" | 只匹配**层内** MAC；稠密对照宽度 d'=√(dim·k0) 同时决定 head 宽度。头 = V·d，在 dim 512–1536 vs d'=23–101 下 **B1 的总 MAC 是稠密的 5–13 倍** |
| 各处"同参数量稠密" | 用 B1 自己的代码把 k0 设成 dim：**没有 RMSNorm / 残差 / RoPE**，不是稠密 LM |

本实验的稠密臂是**标准 pre-norm Llama 块**（RMSNorm + 残差 + RoPE + SwiGLU + tied embed），
且数据、批、验证集、损失归一化、优化器与 B1 臂**逐项对齐**。

## 2. 协议

| | A：B1 生产配置 | B：稠密 等 MAC | C：稠密 6.7× MAC |
|---|---|---|---|
| 结构 | dim4096/k0 8/L32/无残差无 norm/attn-every 8/稀疏 IO(k0e=k0h=16)/head-skip | pre-norm Llama：d=64, L=32, 4 头, SwiGLU 4d, RMSNorm+残差+RoPE, tied embed | 同 B，d=176, hidden 704 |
| 参数 | 1.44M（+attn 0.26M） | 2.63M | 17.31M |
| **MAC/token** | **2.62M** | **2.75M** | **17.66M** |
| 词表 / 数据 | 8198 char / `artifacts/zh_wiki`（train 37.47M id） | 同 | 同 |
| 批 | 32 × seq 64 = 2048 tok/step | 同 | 同 |
| 批采样 | `cursor=(seed*977)%(N-seq-1)`，每步 `+= batch*seq` 回绕 | **逐位复刻** | **逐位复刻** |
| 验证 | 4 固定批 × 32 seq，`base=(eb*977+b*seq*13)%(len-seq-1)`，8064 个预测的 CE 均值 | **逐位复刻** | **逐位复刻** |
| 优化器 | Adam(0.9,0.999)，逐组 L2 clip=1.0，warmup+cosine 到 min_lr | Adam，逐张量 clip=1.0，warmup 100 + cosine | 同 |
| lr | 3e-4 → 3e-5 | 同 | 同 |

**已知差异（如实记录）**
1. warmup 用 100（B1 生产配方是 500，那是为 18296 步调的；本实验每臂 1400–5400 步）。
2. A 有 bigram skip（`--head-skip 1`）；B/C 的对应物是 tied embedding。
3. A 的宽度/层数/lr 是为 18296 步调的；在 30 分钟预算下不是它的最优。这是"按现状比较"的边界。
4. **残差臂没跑成**：`--no-residual 0` 时 `depth_scale=0.125`，attention 输入端塌缩
   （RMS(h) 从 9.4e-10 掉到 2e-35，标定后 `max|q·k|=0`，程序 FATAL）。
   即"给 B1 加残差"在当前实现里**不可直接标定**——这本身是 B1 无残差设计的一个原因。

## 4. 结果（三个匹配轴）

**等 token = 2.87M**（A 的终点，其余两臂插值）

| 臂 | val | Δ vs A | MACs |
|---|---|---|---|
| A：B1 | **5.8865** | — | 7.52 T |
| B：dense64 | 5.9704 | **+0.084（B1 略好）** | 7.89 T |
| C：dense176 | 5.6963 | −0.190 | 50.6 T |

**等墙钟 = 2183 s**

| 臂 | val | Δ vs A | tokens | PPL |
|---|---|---|---|---|
| A：B1 | 5.8906 | — | 2.78M | 361 |
| B：dense64 | **5.2632** | **−0.627** | 11.06M | **193** |
| C：dense176 | 5.6445 | −0.246 | 3.46M | 283 |

**等累计 MACs = 7.52 T**

| 臂 | val | Δ vs A | tokens |
|---|---|---|---|
| A：B1 | **5.8865** | — | 2.87M |
| B：dense64 | 6.0113 | +0.125 | 2.73M |
| C：dense176 | 6.6699 | +0.784 | 0.43M |

三张表合起来说：**B1 的架构在"每个 MAC / 每个 token 买到多少质量"上只是微弱领先
（0.08–0.12 nats），但在"每秒能买多少 MAC"上落后 4.2 倍**。两个效应相抵后，等墙钟
输 0.63 nats。注意 C 的对比同理：稠密把宽度堆到 176 时，每 MAC 的质量暴跌
（+0.78 nats），说明"宽而窄连接"这个形态本身是省 MAC 的——但它省下来的 MAC
被 gather 内核吃掉了。

## 5. 0.63 nats 从哪来（可复算）

```
等墙钟 B1  tokens = 1272.3 tok/s × 2183 s = 2.78M
等墙钟 稠密 tokens = 5065.5 tok/s × 2183 s = 11.06M     （4.0×）
等 token 质量差 = B1 − 稠密 = −0.084 nats（B1 更好，即 5.8865 vs 5.9704）
稠密多出的 8.3M token 换来 −0.627 nats
⇒ 要打平，B1 的等 token 优势必须是 ≈0.71 nats，实际只有 0.084 ⇒ 差 8.5×
```

另一种说法：**每-MAC 效率差 4.2×，而每-MAC 质量优势只有 0.125 nats 的量级。
两者不在一个数量级上。**

## 6. 对 B2 的含义（要改多少才够）

按上面的账，B2 想让"稀疏性价比超过稠密"，需要 **（质量优势 ≥0.7 nats）或（内核效率 ×4.2 且质量优势 ≥0.3 nats）**：

| 改动 | 预期收益 | 依据 | 够不够 |
|---|---|---|---|
| 块对角 + 每层置换（GEMM 化拓扑） | 内核 2–4× | 每连接 2 次非连续 load vs GEMM 的 8–16 复用；见 P31 §6 / P32 §3 | 只够补 4.2× 里的大部分，还要质量优势 |
| attention 窗口化（现在 attention core 占 40% MAC） | MAC/token 最多降 35% | §2 MAC 分解：main 1.05M / attn core 1.05M / head 0.26M / attn proj 0.26M | 有量级，但会伤长程能力 |
| 残差 + norm | 质量（未知），但**当前实现标定不了** | §2 边界 4 | 需要先修 attention 标定 |
| 更好的稀疏拓扑（块对角本身改变函数） | 未知 | — | 要单独测 |

**我的判断**：按这份数据，B1 的性价比路线**没有希望**——不是差一点，是差 8 倍量级的
等效质量优势。除非 B2 能证明"宽稀疏 + 新拓扑"在**等 MAC** 上确实比稠密好 0.5 nats 以上
（现在的实测是 0.12），否则内核再怎么优化都只是把 0.63 的差距压到 0.3–0.4。

## 7. 复现

```powershell
cd <repo root>
# A：B1 生产配置（1400 步 ≈ 37 min）
.\target\release\vmlm-b1-full.exe --sparse-io 1 --dim 4096 --k0 8 --k0-embed 16 --k0-head 16 `
  --k0-attn 4 --layers 32 --no-residual 1 --attn-every 8 --attn-sparse 1 --attn-src-shared 1 `
  --attn-calib 1 --attn-calib-target qk --head-skip 1 --seq 64 --batch 32 --seed 1 --lr 3e-4 `
  --warmup 100 --min-lr 3e-5 --clip 1 --attn-window 1 --parallel-mode inter --persistent-threads 1 `
  --pin 1 --vocab-mode full --chars-per-token 1.0 --data-dir artifacts\zh_wiki --threads 4 `
  --steps 1400 --eval-every 200 --log-every 100 --out-dir artifacts\p32\A_b1
# B / C：稠密臂（等 MAC / 6.7× MAC）
python tools\p32_dense.py --d 64  --layers 32 --steps 5400 --eval-every 200 --tag B_d64_L32
python tools\p32_dense.py --d 176 --layers 32 --steps 1800 --eval-every 200 --tag C_d176_L32

```

## 8. 边界与未做

- **单 seed**，char-level 8198 词表，**每臂 30–39 分钟**，全部仍在瞬态区；A 的配方是为 18296 步调的。
- 稠密臂与 A 的参数不相等（2.63M vs 1.44M）：等 MAC 时稠密天然能多放参数
  （B1 的 attention core 占 40% MAC 却零参数）。所以"等 MAC"这一轴对稠密略有利，而结论是**打平**。
- 未做：残差臂（标定失败）、B1 短预算超参调优臂、multi-seed、更大规模。
